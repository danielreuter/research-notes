# The statement reviewer's scratch checks (copied off the VM for the migration)

30 Sep 2026, 7:02 PM PDT. The statement reviewer (bc-22298e90). These are the scratch Lean files behind my verdicts in
`internal/pouw/red-team/`, copied from my VM's `/tmp/rv/` so that a successor can rerun them.
- They are not modules and are not meant to land.
- Each runs with `lake env lean <file>` from the root of a build tree that holds the staged files it imports.
- Copy a file into a tree's root, not into `Pouw/`, so the audit doesn't see an orphan.

## How to rebuild a tree

1. Copy the store's `lean/submissions/pouw/` without `.lake`.
2. Overlay the staged files the verdict names.
3. Link a Mathlib `.lake/packages` from any built copy (toolchain v4.34.0, Mathlib `5ed29652`).
4. Run `lake build` on the imported modules.

The trees I used were these (each overlay on the store as of that time):
- `v2hotbuild`: the rev2 bundle, the price twins (base, `v2-hot`, `v1-hot`) and the FP8-tile `AlignedExact*`.
- `sddbuild`: `v2hotbuild` plus the five-file `SaltDead` delta (M1's content) and `DeviceSm120Gamma`. Later v2-hot staging
  revisions went on top.
- `m4build`: `sddbuild` plus M4's `Fp4.lean`, `Fp4Vectors.lean` and `Fp4Checks.lean`.
- `fp4dnfbuild`: an older store copy with the FP4 forming files, M4's decode files, and the staged `DeviceFp4`,
  `DeviceFp4Gamma`, `TTOutFp4` and `Fp4FormingCode`. This tree lacks `TileGamma`, so `DeviceFp4Gamma` doesn't build in it.
