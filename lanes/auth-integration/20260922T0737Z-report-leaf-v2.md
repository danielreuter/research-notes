# `verity-vllm/leaf/v2`: algebraic tensor leaves (PROPOSAL, auth-integration lane, 2026-09-22)

Status: **proposal, not the live protocol.** The live scheme is `verity-vllm/leaf/v1` (`leaves.py`: SHA-256 over a
whole tensor's bytes) and nothing in this directory changes until the protocol owner decides. The reference
implementation of this text is `backends/numerical/python/verity_numerical/reference/leaf_v2.py` (tests
`backends/numerical/tests/reference/test_leaf_v2.py`, 3 s, on the 24 captured rows of `fixtures/bench-instances/v1/seeds`);
the costing that motivates it is `note:r20-proof/auth-integration/20260922T0737Z-report-auth-integration`.

## 0. Why

A numerical proof (Candidate A or B) proves `y = f(x, w)` on operands it committed itself. To be a *Verity* proof it
must show those operands are the ones under the Verity roots. Under `leaf/v1` the only private way is to re-hash the
whole leaf in circuit (SHA-256: 3 072-byte rows, 50 compressions, +260-340 % prover time at B = 4096; report §2a).
`leaf/v2` makes the Verity commitment *itself* a Ligero commitment over the same code the proofs use, so binding is two
linear tests the proofs already run (+0.03-0.04 % prover time, no in-circuit hashing, depth +0, private).

## 1. What does NOT change

- The tree above the leaf digest: `node = H("verity-vllm/node/v1", left, right)`, `lift = H("verity-vllm/lift/v1", child)`,
  `ids = H("verity-vllm/ids/v1", id_0, ...)`, `empty`, `levels`, `path_shape`, `open_path`, `fold_path`, `LeafTree`,
  `commitments.json` records (`root`, `leaf_count`, `ids_digest`). A v2 tree is a v1 tree whose level-0 entries are v2
  digests.
- Leaf identity: `(canonical_id, dtype, shape)` are hashed into the digest with the same framing `H(tag, *parts)`.
- The sampling protocol and the obligation addressing: an obligation still names `(tree, rank, word index)`; the word
  index is the row-major index over the tensor exactly as `packed/v1:<framing>:u16le:<count>:<index>` reads it today.
  Only the framing name changes (`packed/v1:verity-vllm/leaf/v2:u16le:<count>:<index>`).
- The verifier's public view: roots, `h_O`, `h_L`, verdict.

## 2. The leaf digest

~~~text
code_text   = "ligero-rs/babybear/n=<n>/k=<k>/l=<l>/R=<R>/w=<w>/coset=<s>"  # fixed per tree, recorded in commitments.json
column      = H("verity-vllm/col/v2",  u32be(chunk), u32be(column), elem_0 || elem_1 || ... )   # elem = u32le BabyBear
chunk_root  = root of levels([column(chunk, c) for c in 0..n-1])       # the v1 node/lift rule over the n columns
leaf        = H("verity-vllm/leaf/v2", canonical_id, dtype, shape_text, code_text, u32be(chunks), chunk_root_0, ..., chunk_root_{m-1})
~~~

Defaults (the campaign's Ligero code, `backends/gkr/PROTOCOL.md` §3): `n = 16384`, `k = 4096`, `l = 3840`, `R = 64`,
`w = 16` (BF16 / u16 words). `p = 2^31 - 2^27 + 1` (BabyBear); the order-`n` subgroup is generated by
`g_n = (31^15)^(2^27 / n)` (Plonky3's two-adic generator `0x1a427a41` for order `2^27`). **Coset shift `s = 31`**
(BabyBear's multiplicative generator, `coset=31` in `code_text`): the codeword lives on `s * H_n`, the message on
`H_k`. Since `31` has order `p - 1` and `H_n` has order `n | p - 1` with `n < p - 1`, `31 notin H_n`, so
`s H_n cap H_k subset s H_n cap H_n = emptyset`: **no codeword symbol is a message symbol** (see §6, hiding).

## 3. Layout: tensor -> tableau rows -> chunks

~~~text
cols            = shape[-1]  (a scalar or 1-d tensor: one row of len(words) columns)
per             = ceil(cols / l)                                 # tableau rows per tensor row
word (r, c)     -> tableau_row = r * per + c // l,  payload_index = c % l
tableau_row j   -> chunk = j // R, row_in_chunk = j % R
payload row     = words[r, s*l : (s+1)*l] as field elements (one w-bit word per element), zero-padded to l
message         = payload (l) || randomizers (k - l)              # randomizers: uniform F_p from the committer's PRG
codeword        = evaluations on the COSET s * H_n (s = 31) of the degree < k polynomial that interpolates the message
                  on the order-k subgroup H_k: codeword[i] = M(s * g_n^i).  NON-systematic: s H_n is disjoint from
                  H_k, so no codeword position carries a message symbol; the message is recovered only by decoding
                  (coset-INTT of any k symbols, or of all n: `reference.leaf_v2.decode_row`).
                  -- SOUNDNESS/PRIVACY FIX 2026-09-22 (lane soundness-fixes; red team F4, `note:r20-proof/red-team-vu/20260922T1042Z-report-redteam-vu`):
                  the first version evaluated on H_n itself, which is systematic (codeword[(n/k) j] = message[j]),
                  and the hiding claim of §6 is FALSE for a systematic code: an opened column at a multiple of n/k
                  IS a payload word in the clear, randomizers or not (the red team read 11 words per proof).
~~~

Chunks of `R` rows bound the column-leaf size (`R x 4 B`); `R = 64` minimises proof bytes at the bench sharing
(report §2d: 44.6 kB/VU; `R = 1` 66 kB, `R = 4096` 64 kB).

## 4. Opening for one word: the transparent (non-ZK) form

Exactly as non-private as the v1 whole-leaf opening; for conformance vectors and `verity.verification.transparent`:

~~~text
TransparentOpening = descriptor (canonical_id, dtype, shape, code_text, chunk_roots)
                   + payload row (l elements) + randomizers (k - l elements)
                   + the other R - 1 rows of the chunk at every column (or the chunk's full codeword matrix)
                   + the v1 path from the leaf digest to the tree root
check: re-encode the row (coset NTT: message on H_k -> coefficients -> evaluations on s H_n); for every column c fold
       column(chunk, c) to chunk_root; leaf digest; v1 path; read payload[payload_index] from the SENT payload row
       (never from a codeword position: there is none)
~~~

(`reference.leaf_v2.verify_transparent_word`.) Range openings are unnecessary: a word is addressed directly.

## 5. Opening inside a numerical proof: the private form (what A / B do)

The proof's own Ligero tableau `U_P` uses the same code (same `n, k`, same subgroup, same field). On the proof's
existing opening round the verifier's column set `Q` (`t` columns, `t <= k - l`) is applied to **both** tableaus:

~~~text
prover -> verifier   for every touched chunk: column(chunk, c) for c in Q, with paths to chunk_root
                     v  = b_irs + sum_i r'_i U_i           (degree < k; U_i over the claimed tensor rows AND the witness rows)
                     q  = b_lin + sum_i r_i(X) p_i(X)      (degree < 2k-1; r_i interpolates the row's coefficient vector on the
                                                            order-k subgroup, zero on randomizer positions)
verifier             every opened column folds to its chunk root; every leaf digest folds to the Verity root;
                     v(eta_c) == b_irs[c] + sum_i r'_i U_i[c]      for c in Q
                     q(eta_c) == b_lin[c] + sum_i r_i(eta_c) U_i[c]   for c in Q
                     sum over the order-k subgroup of q == 0        (every equality constraint U_V[row][j] - U_P[rho][j'] = 0)
~~~

Evaluation points are the coset's: `eta_c = s * g_n^c`. The verifier evaluates `v`, `q` and `r_i` (sent or derived as
coefficient vectors / interpolants on `H_k`) at `eta_c` with the coset scaling; `sum over H_k of q` is unchanged
(it is a coefficient-vector statement). What changed with the non-systematic code: the verifier can no longer read
`U_i[c]` off a systematic position -- it never needed to, the tests only use the opened columns -- and the
committer's "free systematic quarter" (payload already in memory, only `n - k` symbols to write; `direct/encode`
`write_systematic=False`) is gone: all `n` symbols are computed and hashed. The b-encode lane measured the
cosets-only encoder at 31.6 ms vs 32.2 ms for systematic+cosets (`direct/encode/README.md`), so the encoder cost is
unchanged to within noise and no number in `explore.tensor` / `security.zk_cost` moves.

`b_irs` (random codeword) and `b_lin` (random degree < 2k-1, zero subgroup sum) are the proof's blinding rows
(`note:r20-proof/zk-construction/20260922T0737Z-report-zk-construction` §2.1). With geometric position coefficients `rho^j` per claim (PROTOCOL A §12.2's
`rho_geo`) `r_i(X) = alpha_i * G(X)` for one shared interpolant `G`: one NTT per test, not per row. Whole-row
claims (`x`, `w`) and single-word claims (`y`) are the same constraint type.

## 6. Binding and hiding

- **Binding.** A chunk root binds the `n` columns (CRH of `H`). The IRS test binds every claimed row to a unique
  codeword within the unique-decoding radius `e = (n - k)/2` (`(1 - e/n)^t`: the design's own term), and the linear
  test binds the payload (`((k+l)/n)^t`, here at the `(2k/n)^t` quadratic-test degree) -- both terms are the proof's
  existing Ligero terms; the added field terms are `(#constraints - 1)/|F_c|` and `(#rows + 1)/|F_c|`
  (`security.accounting`: 2^-162 and 2^-169 at B = 4096, total 2^-129.5 unchanged). **Consequence:** the v2 digest is
  a commitment, not a hash of the bytes -- two commitments to the same tensor differ (fresh randomizers), and the
  digest alone does not certify well-formedness; the IRS test does, at verification time. A committer who puts a
  non-codeword row under a root has committed to nothing usable for that row (the test rejects; reference negative).
- **Hiding.** Any `t <= k - l` columns of a row with uniform randomizers are uniform and independent of the payload
  (Ligero Lemma 4.15) **provided the opened positions are not message positions**: the lemma's `t x (k - l)`
  randomizer-to-opened-symbols matrix is a Cauchy-type matrix of full rank only when every opened point `eta_c` lies
  outside the interpolation set `H_k`; at a point of `H_k` the row of that matrix is zero (the symbol IS a message
  symbol). The coset domain `s H_n` (§2) makes this hold for every column, and `tests/reference/test_leaf_v2.py::
  test_no_opened_column_is_a_payload_word` opens every column of every chunk and checks it (red team F4 pin; the
  demo `redteam.leaf_v2_exhaustion` now reads 0 words in the clear). `v`, `q` are one-time-padded by the blinding rows. **The budget is per commitment lifetime:**
  the union of all `Q` ever opened against one chunk must stay `<= k - l`. With `t = 191` and `k - l = 256` that is
  one proof per commitment. Either (i) size `l` for the number of proofs a commitment serves (`k - l >= proofs x t`;
  `l = 3328` gives 4), or (ii) re-randomise per proof (weights: 0.6 s per re-commitment of a 1.5 B-parameter model
  on an H100-class GPU, report §3), or (iii) declare the tensor public (open-weights `W`: verifier-side opening,
  no budget). The protocol owner decides which; the reference enforces `t <= k - l` per session only. **Stated
  honestly (red team, `note:r20-proof/red-team-vu/20260922T1042Z-report-redteam-vu` F4 / exhaustion):** the coset fix removes the plaintext leak, not the budget.
  For a long-lived commitment a SECOND session whose columns push the union past `k - l` gives the verifier a
  payload-*equality* oracle (the union's linear relations on the row are consistent with the true payload and with
  no one-bit-off variant: `leaf_v2_exhaustion.json`, `oracle = True` from session 2 at the reduced code), and after
  ~25 campaign sessions the row is determined. The only fix for that is (ii) re-randomisation per session; whether
  Verity pays 0.6 s per weight re-commitment or accepts one private proof per commitment is the protocol owner's
  decision, not this spec's.
- **Adaptivity.** `Q` and the coefficients are verifier coins; under the malicious-verifier layer they are committed
  at step 0 (HM96). Even without step 0 the column openings are simulatable (any `t <= k - l` columns are uniform);
  step 0 is needed for the *rest* of the proof, not for these openings.
- **Encoding injectivity.** A `w = 16`-bit word is one element `< 2^16 < p`; the proof's word wires are the same
  encoding, and its checker range-checks them, so a committer who writes elements `>= 2^16` gets a rejected proof.

## 7. Domain separation (red-team checklist items kept from v1)

- `canonical_id`, `dtype`, `shape_text` and `code_text` are hashed into the leaf digest: a row of another tensor, a
  reinterpretation of the same bytes as another dtype/shape, or a tensor encoded under another code cannot be presented.
- `u32be(chunk)` and `u32be(column)` are hashed into every column leaf: a column of chunk 3 cannot stand for chunk 5,
  a column `c` cannot stand for `c'`; `u32be(chunks)` prevents chunk-list truncation/extension.
- The ids digest and the node/lift path shape are v1's, so an opening cannot be replayed under another tree.
- Randomizers are the committer's secret; they never leave the committer except inside the transparent opening (§4).

## 8. What the committer (vLLM side) computes at capture time

Per tensor: word -> element, `k - l` PRG randomizers per tableau row, one RS encoding per row (matrix-DFT on tensor
cores or an NTT), `n` column hashes per chunk (native SHA-256/Blake3 at 100s of GB/s), the chunk roots, the leaf
digest. Qwen2.5-1.5B, 256-token decode step: 100 k tableau rows, encode 45 ms (H100 @ 0.172 INT8 utilisation; 6 ms with a
Brakedown expander), hash 6.6 GB = 15 ms at the measured 446 GB/s (SHA-256, RTX 4090) -- versus 1.7 ms for `leaf/v1`
over the same words. Weights: 1.0 M rows, 0.45 s encode + 0.15 s hash per (re)commitment. `n = 8192` halves both.

- `schema.py`: admit the framing `verity-vllm/leaf/v2` in `packed/v1:<framing>:...`; the leaf descriptor gains `code_text`.
- `packed.py`: `PackedLeaf` for v2 carries `(canonical_id, dtype, shape_text, code_text, chunk_roots, payload_row,
  randomizers, chunk codewords or column paths, v1 path)`; `check_packed_openings` gets the §4 branch (the SP1 guest
  would re-encode in circuit -- SP1 stays on v1).
- `transparent.py` / `statement.py`: `leaf_hash` for v2 = §2; `OpenedTree`/`TreeTable` unchanged (digest-level).
- `binding.py`: unchanged (it binds `O` to `L`, not leaves to bytes).
- The numerical backends' protocol documents gain the §5 messages on their opening round (PROTOCOL A §5.1 step 5-6,
  PROTOCOL B §5 step 3); `security.accounting` gains the two field terms (already computed by
  `explore.auth_integration.soundness_with_auth`).
- `commitments.json` records `code_text` per tree; every recorded root, conformance vector and the SP1 guest stay on
  v1 until the owner cuts over (both framings can coexist: the framing name selects the checker).
