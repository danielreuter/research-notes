# Merge request: the rest of the Build line `build-v1` (#482, #489, #493, #497), after #479

**Why.** These are the overnight Build workstream's attempts 2–7 (`docs/build-optimization-plan.md` §4). Together with #479 they make every
benchmark Build 2.6–9.0× faster on 32 vCPU, with byte-identical Programs, workload Program and manifest.

`main`'s sweep driver (#470, already merged) exports `VERITY_UNIT_RULE_CACHE` and `BUILD_RAM_BUDGET_GB` for its rows. #482 and #479
are what read them.

**What each changes** (`integrations/vllm` only, except #482's one core line):
- **#482, the unit-rule cache.**
  - The word check's unit rules are stored on disk, keyed by a definition digest: the Definition's canonical entry plus its callees'
    digests. The cache is set by `VERITY_UNIT_RULE_CACHE` or `--unit-rule-cache`.
  - An entry is written only when its JSON round-trip is equal to the rule.
  - The core change is a public `verity.ir.codec.definition_entry(fn)` beside `_encode_definition`.
- **#489, one export per derive.** One `torch.export` and one digest encode per request derive, and no FX stack traces during export.
  The switch goes through `engine.hooks`, the patch owner.
- **#493, streamed `instances.json.gz`.** The file is written in chunks with `json.dumps`, the C encoder, and the rows are never held as
  one list.
- **#497, compose once and beside the derives.**
  - Composition digests each component once and serializes the workload descriptor's canonical JSON once.
  - For B > 1, `global-program --follow` runs beside the derives and loads each component as its derive finishes. `row_stages` starts it
    before `derive_all` and stops it after the summary.

**Behaviour.**
- **Representation:** Program digests, the workload digest and the manifest digest are unchanged on all six benchmark rows. The
  benchmark's `ov.gate=pass` is exactly that check.
- **Artifact identity:** #489, #493 and #497 edit builder sources in `build._CONSTRUCTION_SOURCES`, so `artifact.identity` changes by
  design, and a Program cache keyed on it re-derives once.
- **Circuits:** none change: no Definition, template or lowering. So `circuit-check` has nothing new.
