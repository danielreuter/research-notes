## The result in one paragraph

Both Blackwell-consumer block-scaled FP4 instructions are one adder. `BlockScaledAlignAdd` reproduces **every** captured word:
**8,339,456 nvf4 elements and 7,389,184 mxf4 elements, 0 mismatches**, over 20 tile families including lane fp4-5090's
stored captures (replayed offline), this lane's fit runs and fresh-seed confirmation runs, plus autoproof's probe3 vectors
1,601/1,601 twice. The hardware never emitted `-0` (15.7M elements, 245k `-0` accumulators). The registry now has
`sm120.mma.m16n8k64.e2m1.nvf4` and `sm120.mma.m16n8k64.e2m1.mxf4` **pinned** for arbitrary finite FP32 accumulators; NaN/inf
accumulators and overflow are recorded (D20) and outside the domain.

## The rule (verity.ml.tc.models.BlockScaledAlignAdd)

~~~text
group dot   gd_g  = exact sum of the 16 E2M1 x E2M1 products (quarters)
scaled dot  mant_g = gd_g * ma * mb  at unit weight 2^X_g,  X_g = -2 + ea + eb
            UE4M3 scale -> (ma, ea) = (8+m, e-10), subnormal field (m, -9);  UE8M0 code c -> (8, c-130)
lsb = max( max{ X_g : g participates } - 27,        # scale-exponent anchor (27 = frac_bits)
           acc != 0 ? E_acc - 35 : -inf,            # accumulator window 36 on the EXPONENT FIELD (subnormal acc -> -126)
           -174 )                                   # absolute grid floor
participates = some elementwise product nonzero AND both scale mantissas nonzero (a cancelled dot still anchors)
D = RZ_to_binary32( sum_g trunc_toward_zero(mant_g, lsb) + trunc_toward_zero(acc, lsb) );   any zero total -> +0
~~~

Relation to autoproof's model5: model5's window `lsb = E1 - 41` on the largest addend's msb equals `X - 27` exactly when the
leading group's mantissa is 15 bits wide (and its "hot clip" at `2^-19` is `8 - 27` for exponent fields 15/15) -- the
regime every zero-accumulator chain lives in. It is one grid step off when the leading mantissa is narrower and an
opposite-sign accumulator sits at the edge (D17), it keeps the `-0` accumulator (D16), and it has no exponent-field anchor
or floor (D19).

## sm_100 (B200, tcgen05)

Nothing here transfers by assumption. The sm_120 result is for `mma.sync kind::mxf4nvf4` lowered to `OMMA.SF` on a consumer
die with 1 MMA per warp; B200's `tcgen05.mma kind::mxf4nvf4` is a different instruction (TMEM accumulators, descriptor-fed,
different pipeline widths are plausible, and the datacenter part has no OMMA). To test it: the same probe design (one
instruction per output element, arbitrary FP32 accumulators fed through TMEM, the 20 families incl. the subnormal-regime
ones) needs a `tcgen05` kernel (cta_group::1, `tcgen05.ld` of the accumulator), an sm_100a build, a B200 pod
(~$4-6/h) for ~30 min, and the registry entries `sm100.tcgen05.mma.e2m1.{nvf4,mxf4}` (currently `unprobed`, model None).
