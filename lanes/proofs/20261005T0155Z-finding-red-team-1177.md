# Red-team review of PR #1177: the zk inner prover checks before it speaks

PR: https://github.com/danielreuter/verity/pull/1177, branch `cursor/zk-inner-selfcheck-95d4`, head
`688b2c40ccec089d30254d14d8c36dce8bedb052`, base `5049de02f`. Reviewed for the proofs coordinator (bc-8416bc72), 6:55 PM PDT,
Oct 4.

**Verdict: GRANT.** Nothing blocks. When the batched constraint fails, the prover stops after the batching coins' round and
sends nothing that depends on the failing sum. The honest proof is byte for byte main's, every existing verdict is
unchanged, and outside code nothing turns the check off. Four notes below are non-blocking.

## What was checked

1. **Ordering.** The check (`zk_veil.rs:997`) runs right after `ch.sample_f128_vec(cons.len())` returns γ, and before
   `observe_bytes(tau_commit)`, β, `Y` and the queries. `LiveChallenger` (also under `Masking`, `Logging` and `Framer`)
   puts observations on the wire only at a squeeze, so `pending` is empty when the check returns. Before γ the prover sends
   `final_c'`, masked by `h_fc`, and `[ρ, σ] = [ε h_fa + h_tx, h_fb + h_ty]`, uniform through `h_tx` and `h_ty`, which
   appear only in the triple. Neither depends on the witness or the failing sum.
2. **The sum.** `batch` returns `(l.a, l.c)` for `l = Σ γ_k cons_k`, so `t + ⟨c, p.h⟩ = l.eval(p.h)`. The verifier's
   `⟨c, Y⟩` zips `c` (length `s`) with `Y` (length `s + K_PAD`), so it reads `Y[..s] = h + β μ`, and `⟨c, Y[..s]⟩ + t + βτ =
   ⟨c, h⟩ + t` in GF(2^128), where `+` is `−`. The check uses the committed pads `p.h`, the ones `Y` is built from. The
   prover's `cons` are the verifier's: the same `replay` over the same masked messages and coins, its `comb_partial`, which
   is public, the sent `s_hat_v`, and `Level0ZkRecord`, whose `target` is the opening's absorbed target, whose `ood`, `rho` and
   `challenges` are β coins and coins, and whose `t_prime` is sent. So V* and the simulator compute the same `(c, t)`.
3. **Repetitions.** On the CPU, reps and tables run in sequence: a stop returns from the session closure before rep 1's
   stream opens. On the GPU overlap path, rep 1's device run opens its stream only in its first round's callback, after
   joining rep 0's `zk_finish` thread, and panics before opening when rep 0 stopped. Its hook makes no call, because
   `cached` is set. The other order, where rep 0 passes and rep 1 stops, sends rep 0's `Y` only after rep 0's own check
   passed. With `res = Err`, `session_finish` sends only `Finish`, never the proofs.
4. **The stop path.** No `Drop` flushes a challenger, `Masking` or `Logging`. The `PROVER-STOPPED` text and
   `constraints_failing_on_pads` stay in the prover's local record. `prove_inner` has exactly one caller (`zk_finish`), and
   the CPU, `FC_ZK_FRAMED`, GPU-sequential and GPU-overlap paths all reach it with the rep's `self_check`. M0 has no inner
   proof. `prove_sessions` has no retry.
5. **Skip's reach.** `Plan` derives only `Clone, Default`, so no file, JSON or plan can carry `zk_self_check`. No env var
   reads it. `prove`, the only mode that connects to a TCP verifier, uses `Plan { gpu, tables, split, ..default }`.
   `zero_witness` is set only in `seed-injection` harness modes (`zkstat`, `fresh_dummy`, `gk_simulate`, `zkgk`) and in one
   selftest case, all against in-process verifiers. The dummy is zero apart from `write_regions`, whose regions are `Digest`
   (the committed `b ‖ c`) and the public input words, so it holds no secret.
6. **Honest behaviour.** Local lib tests on a b684b12 checkout with this tree's patches: 79 passed and 1 ignored
   (`sha512`), 86 passed and 2 ignored (`sha512,glue,seed-injection`), the recorded check's counts. A probe of main's
   `prove_inner` at `5049de02f` on the test's honest fixture gives `a817dca1…e35f` over 4 rounds, the pinned digest.
   Mutants: moving the check after the τ commitment's observe fails "nothing observed after the batching coins", and moving
   it after β fails the two-round comparison. The selftest diff between `r20261005-000202-e8c2` and
   `r20261005-000306-10f9` changes only per-run nonces and roots, plus the new case, which passes. The "after" run's rc 1 is
   the `"TODO"` digest placeholder at `3b1db96bc`. Check `r20261005-001849-3cc5` passed, with fresh Rust tests at 79 and 86.
   Every `Stop` control proves a true witness: the `*_claim_false` cases swap only the verifier's `public_sha512`. Every
   `Skip` control fails by design, and `output_row_committed_false` proves the false instance.
7. **§5 and §7** state the rule, its quantity and its two exceptions accurately (see N2 for §9).
8. **Other sites.** `extra_claims` is region claims only, so the PR's "Not covered" list (region `s_hat_v`, Ligerito level 0
   and levels ≥ 1, M0) is complete for the inner proof. No other value derived from a failing check goes out.

## Non-blocking findings

- **N1 (non-blocking, doc), `backends/flock/live/src/zk_veil.rs:1110`.** `failing`'s doc says "a dishonest prover's proof
  carries on to the verifier". It now does so only under `SelfCheck::Skip`. Fix: "(none for an honest prover; under
  `SelfCheck::Skip` a negative control's proof carries on to the verifier, under `Stop` `prove_inner` stops)".
- **N2 (non-blocking, doc), `backends/flock/live/PROTOCOL.md:419` and `:429`.** §9 calls the extraction run and
  `fresh_dummy` "the honest prover on a dummy witness". With `Stop` that prover would always stop at γ, and the claim
  "distributed as a real one until the proofs" holds because these runs skip the check. Fix: add "(§5's self-check skipped)"
  in both places.
- **N3 (non-blocking, test), `backends/flock/live/src/bin/flock-circuit.rs:3250`.** `zk_failing_witness_stops_before_tau`
  checks rep 0's stream only. Fix: also require that the view has no `Req::Open` or `Req::Round` for
  `rep_stream(TABLE, 1)`, so the case pins "a stop in rep 0 stops the session". That matters most for the GPU overlap path,
  where rep 1's device run starts before rep 0's finish and which this PR didn't run.
- **N4 (non-blocking, doc), `flock-circuit.rs:2964` with `record_case` at `:3586`.** The `Skip` controls tamper the
  witness of the real `--instances` file, and `--record-dir` keeps their proofs, whose `Y` exposes `⟨c, h⟩ + t` of that
  tampered witness. This predates the PR and stays in-process. Fix: §5's exception paragraph could add that the selftest
  runs only on instances with no secret, because its controls' records carry such `Y`.
- Optional wording, `PROTOCOL.md:319`: "refuses no coin" could read "refuses no further coin". It relies on the refusals
  above covering every coin at which an honest constraint could fail.
