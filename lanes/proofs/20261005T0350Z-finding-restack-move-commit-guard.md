# restack.py takes the move branch's head as `--move-commit` and reports clean

## What happens

The tree it produces undoes the move's hand fixups.

```
python3 tools/move/restack.py 688b2c40c --move-commit 6ffeb868 --dry-run --json
```

- It reports status clean, result `2b3a88010952`, with the base given as `b1562b69d`, a tree that is already moved.
- The correct call passes the last commit `layout.py` generated: `--move-commit c58b2fa30` (parent `9e0cf748f`) with
  `--onto 6ffeb868`. That gives `12ebb065b`.
- The two results differ in 9 files outside the branch:
  - `tools/tc_probe_fp4/emulation.py` aliases `verity_catalog.silicon.models` to itself instead of to `verity.ml.tc.models`;
  - the commitments suite's inputs drop vLLM's check codes;
  - `lean-deps.json` is rekeyed.
- The fix: refuse a `--move-commit` whose parent tree is already moved, or that isn't marked as generated by `layout.py`.
- #1175's own dry run used `ed38fdbcc`, two generations old.

## Also seen

- Every restacked `uv.lock` flips `revision = 5` to `revision = 3`. That's the rerun of `uv lock` with uv 0.12.21; the
  rest of the file is identical. Pin uv, or keep the move's header.
- `git merge-tree` runs the `lean-audit` merge driver from the caller's checkout, so lock merges use whatever
  `tools/lean/merge.py` the caller has checked out. In this run that was main's, the same as the move's.

## Proofs' branches

All carry across cleanly once each has merged main, which every branch except #1177 needs anyway:
- #1179, #1170, the flock-spec split and canonical V1: one `backends/flock/verifier/PROTOCOL.md` hunk, the same one they
  have with main.
- #1170 and the split also need two lock records rebuilt with `audit.py --update`.
- #1177 restacks clean.
- #999, #1052 and #1088 need the restack itself, not a plain merge: `test_lean_universal.py` imports modules the move
  deletes, and only the rerun rewrites those imports.

Main is about 75 files past the move's base, so rerun this check on the regenerated move commit.
