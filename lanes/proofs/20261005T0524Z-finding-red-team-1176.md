# Red-team review of PR #1176: circuit-check cache v3 (a pure move of a registry module reuses every target)

PR: https://github.com/danielreuter/verity/pull/1176, branch `cursor/circuit-check-descriptor-key-8c79`, head
`7800f456105b07348db654a5bfa629339983938c` (unchanged throughout the review), merge base with `main` `8216f316c` (#1126's
red-team head). Evidence (the red-team tests, the proposed fix diff, every test log, the merge-base comparison, the real-tree
scan): `art:b472e096ce597cb740fec483764ff4cf1bdd43410f8c136c4275f733fa14ae83`.

## Verdict: SHIP-WITH-FIXES (four required fixes, about 25 lines in `cache.py`, all tested)

The PR's claim is that a hit means every module and `targets.py` unit the target held is unchanged except for where its modules
are. Four edits break that claim, and none of them is on the not-covered list. In each, a fresh run's verdict changes while
the cache still hits. Three are new in v3: the move-following in `_moved`, the refresh in `lookup`, and the import ordering in
`_commuted`. The fourth, R2, is older: v2's kernel naming had it too, but this PR rewrote `_where` and its description claims
the opposite. None of the four is reachable by an edit to the real tree today, as far as I found. Each fix is a few lines and
costs no pure-move hit. I applied all four as a scratch diff (`proposed_fixes.diff` in the art) and ran three sets of tests:

- The 21 existing tests (`test_cache.py` + `test_cache_redteam.py`) still pass.
- The real-tree cache tests in `test_circuit_check.py` still pass.
- The five red-team tests for these findings turn green.

Two more findings and a nit are recommended, not required. N1 needs only a docstring correction: the behaviour is deliberate
and older than this PR. N2 and N3 are hardening that #1126 had too and that doesn't reach the merge gate. With R1 to R4 in, the
cache is fit to gate `check`.

No label is applied, since the verdict is not GRANT.

## Required fixes

### R1 (v3, unlisted; contrived today): a module reached only through a plain `import a.b` is relocated by content

The edit:
- `syn/pkern.py`'s evaluator reads `lib.consts.MASK` through `import lib.consts`.
- Move `lib/consts.py` to `lib/fam/consts.py`.
- Leave a new module at the old name, `from lib.fam.consts import *` followed by `MASK = 0x00FF`. That is a compatibility shim
  that also narrows one value.
- Leave the import line in `pkern` as it is.

A fresh run computes `[6]`. The cached run reuses `[262]`.

Why the key misses it: `_Norm.visit_Import` keeps `import a.b` by name and records no site. So no site leads `_moved` to
`lib.consts`, and it falls back to `_loaded`, "the one module of that content this process imported before any check". That
is now `lib.fam.consts`, so `_moved` maps `lib.consts` there while `pkern` still binds the new `lib.consts`. A swap of two
modules' contents, with plain-importing importers left alone, gives the same result.

This contradicts the PR body's "a rewritten import line that now binds a different module is caught" for plain imports, and
the module docstring's rule that a module no site leads to is found that way.

Real tree: 28 in-tree modules are plain-imported somewhere, and none is reached only through plain imports (`scan_tree.log`).
The edit also needs a move plus a different module at the old name, so it is contrived today.

Fix (2 lines): in `_Norm.visit_Import`, record a site `(-1, prefix, None)` for each dotted prefix of an import without
`asname`. No pure move loses a hit: a plain import spells its module's name inside the importer's digest, so moving that module
already changes the importer.

Test: `test_a_module_a_plain_import_binds_is_held_at_the_name_it_binds`.

### R2 (v2 and v3, unlisted; the real tree's shape, latent today): a kernel registered through a wrapper is named by the wrapper

The edit: `syn/krows.py` registers `kreg.register("SynTop_v1", kimpl.add)`, and the edit changes it to `kimpl.sub`.
`kreg.register` is `kernel_registry.register`'s shape: `register_kernel(target, _batch(fn))`, where `_batch` returns a `run`
closure. A fresh run fails `correspondence/kernel-mismatch`. The cached run reuses the pass.

Why the key misses it:
- `_kernels_now` holds `_where(kn.fn)`, which names `run`: `kreg`'s content, the qualname `_batch.<locals>.run` and `run`'s own
  definition. That is the same whichever function `run` closes over.
- `_where` also drops `functools.partial` arguments, and that loss is likewise unrecorded.
- `syn/krows.py` ran only at import, so no check holds it.

The PR body says "Registering a different function, or editing the one registered, changes it". That is false for any
wrapped kernel. It also reproduces at the merge base, where v2 names `run` by path and line (`merge_base_comparison.log`).

Real tree: `kernel_registry._batch` doesn't use `functools.wraps`. So every vLLM kernel registered through
`kernel_registry.register` gets the same `_where`, and its `kernels` entry differs from another's only in kernel name, domain,
version and sampler. It is latent today. Each of the 36 registrations (`scan_tree.log`) is one of these:
- a function or lambda named directly;
- a wrapper defined in the registering module, which runs whenever the kernel runs and so holds that module (`rows._instance`,
  `dense_rows._claim`, `twins._instance`);
- a registration for a Definition the registering module itself defines (`verity.ml.gemm`).

The first registration of a function defined elsewhere, from a module whose code doesn't run during the kernel call, exposes
it.

Fix (about 15 lines):
- `_RecordedKernels.setdefault`, which is how `register_kernel` writes, notes the nearest in-tree `<module>` frame that
  registers each key.
- `_note` adds those files to the open recording.
- A target that looks up a kernel then holds the module that registered it, by name and content, and `_moved` follows a move
  of it.

An alternative is to fold closure cells and partial arguments into `_where`. That would not see `rows._instance`'s `RowKernel`
cell, whose `fn` decides the kernel. If neither code fix lands, the claim must go and this edit must be listed as not covered.

Test: `test_a_kernel_registered_through_a_wrapper_reruns_its_target_when_the_function_registered_changes`.

### R3 (v3, unlisted; contrived): an entry stored again after a move lacks the package its module moved into

The edit, in order:
1. Move `lib/lconsts.py` into a new package `lib/fam/`, whose `__init__.py` is a docstring, and rewrite its one import. SynL
   hits and is stored again, then hits again.
2. Edit `lib/fam/__init__.py` to run `import lib.fam.lconsts as _c; _c.MASK = 0x00FF`.

A fresh run computes `[6]`. The cached run reuses `[262]`.

Why the key misses it:
- `lookup` stores the entry again with only the recorded names renamed.
- A run holds each module's parent packages ("and its parent packages"), so a fresh entry would hold `lib.fam`. The stored
  entry doesn't.
- `_moved` accepts the new parent's trivial `__init__` once, at the move, and later lookups never see the parent again.

So the entry stored again is not "what a run would record", which is what `lookup`'s docstring says it is. The edit that
exploits this has a package `__init__` patch a submodule's state, which is contrived.

Fix (2 lines): before `store` in `lookup`, add each renamed module's parent packages to `got["modules"]`.

Test: `test_an_entry_stored_again_after_a_move_holds_the_package_the_module_moved_into`.

### R4 (v3, unlisted; contrived today): `_commuted` reorders imports where they don't commute

The edit: `syn/okern.py` sets `MASK = 0x00FF`, then:

```python
try:
    from syn.wide import MASK
    import syn_absent_backend as fast
except ImportError:
    fast = None
```

The edit swaps the two `try` lines. That is the order an import sorter writes: plain `import` before `from`, which is
isort's and ruff's default. The failing import now comes first, so `MASK` keeps its fallback. A fresh run computes `[6]`. The
cached run reuses `[262]`, because `_commuted` sorts the run by the names it binds and both orders digest alike.

The same holds inside `with contextlib.suppress(ImportError):`. Also, a `from __future__` import moved below another import
doesn't compile, but digests the same as the valid module.

Real tree: there are 15 `try` bodies whose imports `_commuted` reorders (`scan_tree.log`, e.g. `compiled_norm_literal.py:37`).
In none of them would a reorder change which names end up bound, so this is contrived today.

Fix (3 lines): leave the body of a `Try`/`TryStar`/`With`/`AsyncWith` uncommuted, and end a run at a `__future__` import.

Tests: `test_imports_in_a_try_body_do_not_commute` and `test_a_future_import_keeps_its_place`.

## Recommended (not required)

### N1 (older than v3, deliberate; documentation): an enumerated package's modules are held by their listing, not their content

The setup: `syn/plug.py` is imported only by the enumeration, and runs `reg.KINDS["SynOther_v1"] = "plugged"`. SynOther's check
reads `reg.KINDS`. The edit changes `"plugged"` to `"replugged"`: a fresh run reads `replugged`, and the cached run reuses
`plugged`.

Why the key misses it: `_moved` compares an enumerated package's modules only when a name enters or leaves the listing. That is
deliberate: `test_editing_a_registry_module_no_target_resolves_reuses_every_target` requires it, and the test exists at the
merge base too, where v2 held no enumerated module at all. But the docstring ("held by the modules it lists, each by its
content") and the PR body ("each by content") say more than the hit rule does.

Real tree: I found no check that reads a table a registry module fills at import, other than these:
- `_KERNELS`, held exactly by `kernels`;
- the Definition registry, held through descriptors (and `REGISTRY.add` refuses a second object for one id);
- `ir_lower.PIECES`, which is filled only by modules that `ir_lower` imports.

Fix: correct the docstring and the PR body to say the listing is held, with content used only to follow moves. Then list as
not covered "a value a module only the registries import leaves in another module's state at import, other than a kernel
registration or a Definition".

Test: `test_an_edit_to_a_module_an_enumerated_package_lists_is_no_move`. It stays red by design; drop it after the doc fix.

### N2 (older than v3): a module edited after its import and before the check stores the old code's verdict

The setup: the registries import `syn.prims` before any check. Then an edit of its evaluator lands, say from an editor saving
during a long `--all` run. The process keeps running the old code. But the worker's `seen` and the parent's `store` both
digest the file after the edit, so they agree, and the old value is stored under the new source's digest. Every later run then
reuses it. The cached value is `[264]`, where a fresh run computes `[8]`.

This contradicts "Only a verdict is stored, of the tree its check read". It reproduces at the merge base.

Exposure: local `--all --cache` runs on a tree being edited. The merge queue builds verdict packs only from recorded runs on
clean commits (`tools/check/verdicts.py`), so the gate isn't exposed.

Fix: record each in-tree module's source digest when it is executed. The `exec_module` hook covers modules imported while
tracing, and `_stale_bytecode` covers modules imported before. Then refuse to store when a held module's digest differs.

Test: `test_a_module_edited_after_it_was_imported_and_before_the_check_ran_stores_nothing`.

### N3 (older than v3, nit): the key omits `sys.flags.optimize`

A run under `-O` or `PYTHONOPTIMIZE` strips asserts, so its pass is reused by a run without them, and the other way round.
Fix: add `"optimize": sys.flags.optimize` to `key`.

## Probed and clean

- **Normalization.** `ast.dump(include_attributes=False)` drops only positions; docstrings, constants, annotations and
  decorators stay. `import M as N` becomes `<import as N>` with a site. `from` imports are cut one name each, with sites. A
  relative import is re-resolved from the module's package (`_relative`). `from P import m` names `P.m` when that is a module.
- **`_moved` cases that miss correctly:**
  - an ambiguous renaming, i.e. two loaded modules of one content (`_loaded` needs exactly one);
  - a swap of modules reached by `from` sites (sites are paired, and `locate` compares content);
  - a move plus a same-named different module, when an importer's site leads to the old name;
  - two modules mapped to one, since injectivity is checked.
- **`_moved`, pinned names and anchors.** `named`, `missing` and `at` stay pinned. Every read of `__file__`, `__name__`,
  `__spec__`, `__path__`, `__loader__`, `__cached__` or `__package__` anchors a module (`_ANCHORS`). A string-named import
  (`import_module`, a called `__import__`) lands in `named`. `other.__file__`, `__module__` and `co_filename` are on the
  not-covered list.
- **`_commuted`.** Two imports that bind one name keep their order (stable sort, the later wins). `import *` ends a run. The
  side-effect order of first imports is on the not-covered list.
- **Refresh.** These all behave: a move then a move back; a move of A then a new A at the old name; repeated lookups after a
  move, where the second is exact. R3 is the only exception.
- **`_stale_bytecode` and `_taken`.** They follow `importlib._bootstrap_external`:
  - timestamp pycs, by mtime in whole seconds and size; a same-second edit of the same size is caught by comparing code
    objects;
  - checked-hash pycs, by source hash; unchecked-hash pycs are taken, then their code is compared;
  - `check_hash_based_pycs` set to `always` or `never`;
  - `-O`, through `spec.cached`'s optimized pyc and `compile` at the same level;
  - `PYTHONDONTWRITEBYTECODE`: no pyc, so the module was compiled from source;
  - modules imported while tracing are compiled from source by the loader hook.

  A sourceless in-tree `.pyc` (untracked, with no `.py` beside it) is not handled. That is contrived.
- **The descriptor.**
  - `cli.target_key` passes `roots[0]`, and `roots` is always `[fn]` (cli.py:105), so nothing is dropped.
  - The closure covers body nodes and `FunctionDefinition` statics, each by its canonical entry's digest. A body that fails
    to build gives `error:<Type>`.
  - `check.py` runs `circuit-check --all --cache` through the same `target_key`.
- **#1126's fixes hold.**
  - `_RecordedKernels` records a lookup that finds none (through `get`, `__getitem__` and `__contains__`, with enumeration
    recorded as `*`).
  - `_model_list` returns None for duplicate labels.
  - `os.fork` is in `UNTRACEABLE`.
  - `test_cache_redteam.py` is byte-identical to the note's copy (sha256 `98c25191…0cecc`), and its 3 tests pass together
    with `test_cache.py`'s 18 (21).
- **Copy-then-edit of a Definition module** fails closed: `REGISTRY.add` refuses a second object for one id.

## The red-team tests (`tools/circuit_check/tests/test_cache_redteam_1176.py`, verbatim)

```python
"""Red-team probes of `circuit_check.cache` v3 (PR #1176): edits that change a target's verdict while its entry is still reused.

Each end-to-end test runs the synthetic tree of `test_cache`: a cold run, the edit, a run under a fresh cache (the verdict as
it is now), and a run under the first cache.  A test fails where the cached run reuses the stale entry.  The fresh caches sit
beside the tree, so no listing of the tree sees them."""
from __future__ import annotations

import ast
import json
import os
import subprocess
import sys
from pathlib import Path

from test_cache import FILES, HARNESS, KERNEL_FILES, REPO, _bindings, _edit, _entry, _move


def _tree(tmp: Path, extra: dict[str, str]) -> Path:
    subprocess.run(["git", "init", "-q", str(tmp)], check=True)
    for rel, text in {**FILES, **extra}.items():
        p = tmp / rel
        p.parent.mkdir(parents=True, exist_ok=True)
        p.write_text(text.lstrip("\n"))
    return tmp


def _harness(check: str = "check") -> str:
    h = HARNESS if check == "check" else \
        HARNESS.replace("from syn import catalog, check\n", f"from syn import catalog\nfrom syn import {check} as check\n")
    return h.replace('print(json.dumps({"stats"',
                     'print(json.dumps({"targets": {t["target"]: {k: t.get(k) for k in ("failures", "value", "regkind")}'
                     ' for t in rep["targets"]}, "stats"')


def _run(root: Path, harness: str, cache: str = "cache") -> dict:
    where = 'root / "cache"' if cache == "cache" else f'Path({str(root.parent / f"{root.name}-{cache}")!r})'
    h = harness.replace('cache=root / "cache"', f"cache={where}")
    env = {**os.environ, "PYTHONDONTWRITEBYTECODE": "1"}
    r = subprocess.run([sys.executable, "-c", h, str(root), str(REPO)], capture_output=True, text=True, cwd=REPO, env=env)
    assert r.returncode == 0, r.stderr
    out = json.loads(r.stdout.strip().splitlines()[-1])
    assert not out["stats"]["untraced"] and not out["stats"]["errors"] and not out["stats"]["changed"], out
    return out


def _codes(fails: list[dict]) -> list[str]:
    return sorted(f"{f['check']}/{f['code']}" for f in fails)


def _add_binding(root: Path, name: str, module: str, attr: str, family: str) -> None:
    _edit(root, "syn/catalog.py", "\nBINDINGS = [",
          f"\ndef {name}():\n    from syn import {module}\n    return [bind({module}.{attr})]\n\n\nBINDINGS = [")
    _bindings(root, f'(("_{name}_roots",), {name})', families=(family,))


#: a package no enumerator lists, and a primitive whose evaluator reads its constant through a plain ``import lib.consts``
PLAIN = {
    "lib/__init__.py": "",
    "lib/consts.py": "MASK = 0xFFFF\nBITS = 16\n",
    "syn/pkern.py": """
import lib.consts
from verity.ir import primitive

from syn.prims import V


@primitive("SynPx", 1, [("a", V), ("b", V)], V)
def SynPx(a, b):
    return (a ^ b) & lib.consts.MASK
""",
    "syn/pdef.py": """
from verity.ir import composite

from syn.pkern import SynPx
from syn.prims import V


@composite("SynP", 1, [], lambda S: ((("a", V), ("b", V)), V))
def SynP(B, S, a, b):
    return B.call(SynPx, a, b)
""",
}


def test_a_module_a_plain_import_binds_is_held_at_the_name_it_binds(tmp_path):
    """``import lib.consts`` records no import site (`_Norm` keeps it by name), so `_moved` finds a changed `lib.consts` as
    "the one loaded module of its old content".  Moving `lib/consts.py` into `lib/fam/` and leaving at the old name a module
    that takes the moved one and narrows ``MASK`` maps `lib.consts` to `lib.fam.consts`, while `syn.pkern` still binds and
    reads `lib.consts`: a fresh run computes the narrowed value."""
    root = _tree(tmp_path, PLAIN)
    _add_binding(root, "pxor", "pdef", "SynP", "SynP_v1")
    h = _harness()
    cold = _run(root, h)
    assert cold["targets"]["SynP_v1"]["value"] == [(3 ^ 0x0105) & 0xFFFF]
    assert "lib.consts" in _entry(root, "SynP_v1")["reads"]["modules"]
    _move(root, "lib/consts.py", "lib/fam/consts.py")
    (root / "lib/consts.py").write_text("from lib.fam.consts import *  # noqa: F403\n\nMASK = 0x00FF\n")
    assert _run(root, h, cache="fresh")["targets"]["SynP_v1"]["value"] == [(3 ^ 0x0105) & 0xFF]
    warm = _run(root, h)
    assert "SynP_v1" not in warm["hits"], (
        f"SynP_v1 reused its entry (value {warm['targets']['SynP_v1']['value']}) where a fresh run computes [6]")


#: a module the enumeration imports, which registers into a table another module owns (as a kernel module registers into
#: `_KERNELS`): no check runs any of it.  The check reports what it looks up as ``regkind`` (the report's own ``kind`` is the
#: target's)
PLUG = {
    "syn/plug.py": 'from syn import reg\n\nreg.KINDS["SynOther_v1"] = "plugged"\n',
    "syn/pcheck.py": """
def check_definition(fn, opts, *, memo, pins, as_call=None, **kw):
    from syn import reg
    return {"failures": [], "warnings": [], "regkind": reg.KINDS.get(fn.id)}
""",

def test_an_edit_to_a_module_an_enumerated_package_lists_is_no_move(tmp_path):
    """SynOther's check reads ``reg.KINDS``, which `syn/plug.py` fills at import; SynOther holds `syn.plug` only through the
    enumerated package `syn` (`enums`, each module by its content).  An edit of `syn/plug.py` changes that record, and
    `_moved` accepts it: a module listed both before and now is not compared.  Pre-existing (v2 held no enumerated module) and
    deliberate (`test_editing_a_registry_module_no_target_resolves_reuses_every_target`), so the fix is the docstring's: say
    the listing is held, not each module's content, and list this edit as not covered."""
    root = _tree(tmp_path, PLUG)
    h = _harness("pcheck")
    cold = _run(root, h)
    assert cold["targets"]["SynOther_v1"]["regkind"] == "plugged"
    rec = _entry(root, "SynOther_v1")["reads"]
    assert "syn.plug" not in rec["modules"] and "plug" in rec["enums"]["syn"]
    _edit(root, "syn/plug.py", '"plugged"', '"replugged"')
    assert _run(root, h, cache="fresh")["targets"]["SynOther_v1"]["regkind"] == "replugged"
    warm = _run(root, h)
    assert "SynOther_v1" not in warm["hits"], (
        f"SynOther_v1 reused its entry (regkind {warm['targets']['SynOther_v1']['regkind']!r}) where a fresh run reads"
        " 'replugged'")


#: `kernel_registry.register`'s shape: core holds a wrapper (`_batch.<locals>.run`) defined in the registry module, closing over
#: the function registered, which `syn/krows.py` names from `syn/kimpl.py`
WRAPPED = {
    "syn/kreg.py": """
from verity.evaluation import register_kernel


def _batch(fn):
    def run(*arrays, **statics):
        return fn(*arrays, **statics), None
    return run


def register(target, fn, **kw):
    return register_kernel(target, _batch(fn), **kw)
""",
    "syn/kimpl.py": """
import numpy as np


def add(a, b):
    return (a.astype(np.uint64) + b) & 0xFFFF


def sub(a, b):
    return (a.astype(np.uint64) - b) & 0xFFFF
""",
    "syn/krows.py": 'from syn import kimpl, kreg\n\nkreg.register("SynTop_v1", kimpl.add)\n',
    "syn/corr.py": KERNEL_FILES["syn/corr.py"],
}


def test_a_kernel_registered_through_a_wrapper_reruns_its_target_when_the_function_registered_changes(tmp_path):
    """SynTop's kernel is ``run``, a closure in `syn/kreg.py`; `_where` names it by that module's content, its qualname and its
    definition, the same whichever function it wraps.  `syn/krows.py`, which chose ``kimpl.add``, ran only at import, so no
    check holds it: registering ``kimpl.sub`` instead keeps every read SynTop holds, and a fresh run fails
    `correspondence/kernel-mismatch`."""
    root = _tree(tmp_path, WRAPPED)
    h = _harness("corr")
    cold = _run(root, h)
    assert cold["targets"]["SynTop_v1"]["failures"] == []
    rec = _entry(root, "SynTop_v1")["reads"]
    assert list(rec["kernels"]) == ["SynTop_v1"]
    _edit(root, "syn/krows.py", "kimpl.add", "kimpl.sub")
    assert _codes(_run(root, h, cache="fresh")["targets"]["SynTop_v1"]["failures"]) == ["correspondence/kernel-mismatch"]
    warm = _run(root, h)
    assert "SynTop_v1" not in warm["hits"], (
        f"SynTop_v1 reused its entry (failures {warm['targets']['SynTop_v1']['failures']}) for a correspondence/kernel-mismatch")


#: a constant in a package no enumerator lists, read by a primitive's evaluator through a ``from`` import
MOVED = {
    "lib/__init__.py": "",
```
