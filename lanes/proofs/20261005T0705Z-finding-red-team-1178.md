# Red team: PR #1178 at c8443978ec6892f1cd91cd09989e457a1b2a6e8f

**Verdict: NOT GRANTED.** `backends/flock/tool.py` is sound. `_source_digest` in
`backends/flock/python/verity_flock/class_statement.py` gives two false hits once `verity` is a namespace package split
across members, which is the layout the move produces. A false hit means the stage cache reuses a staged statement built by
other code. On today's layout neither is reachable: all five digested names are regular packages with one portion each.

Reviewed on the merge of origin/main a592a5567 with c8443978e (tree 30b076df1). The flock files in that tree are identical
to the PR head.

## False hit 1: a portion holding only namespace subpackages is not hashed

The `any(pkgutil.iter_modules([r]))` filter drops every portion whose top level holds no module. `iter_modules` does not list
a directory without `__init__.py`. So a member that ships only part of a split subpackage, for example `verity/ml/tc/...`
where `verity/ml` is itself split, is skipped, even though Python imports its files.

Reproduction: portions `a/ns/m.py` and `b/ns/sub/mod.py`, with no `__init__.py` anywhere. With `PYTHONPATH=a:b`,
`import ns.sub.mod` prints `Y = 1`. Edit `b/ns/sub/mod.py` so that it says `Y = 2`, and the import prints 2, but
`_source_digest()` is unchanged. This is `test_a_portion_holding_only_a_namespace_subpackage_is_hashed` below.

## False hit 2: overlapping portions get one digest in either order

Files are sorted by path under the package, and the hash covers only that path and the file's sha256. So the digest is a
function of the multiset of (path, content) pairs and does not record which portion supplies a module. Python imports the
first portion on `sys.path`. The old code walked portions in search order, so it gave a miss here, which is safe.

Reproduction: `a/ns/x.py` (`V = 1`) and `b/ns/x.py` (`V = 2`). With `PYTHONPATH=a:b` the import gives 1, and with
`PYTHONPATH=b:a` it gives 2. `_source_digest()` returns the same value both ways (it was `3ac3230c…` in my run). This is
`test_portions_that_overlap_never_share_a_digest_across_orders` below.

## Tests: `backends/flock/tests/test_class_statement_redteam_1178.py`

At c8443978e, the two false-hit tests fail and the other two pass. With the fix below, all four pass. Run them from a
checkout so that `verity_flock` imports from that checkout (the first test asserts it). For example:
`uv run --package verity-flock pytest backends/flock/tests/test_class_statement_redteam_1178.py`, or `python -m pytest`

```python
    pp = ":".join(str(tmp_path / o) for o in order)
    r = subprocess.run([sys.executable, "-B", "-c", stmt], env={"PYTHONPATH": pp}, capture_output=True, text=True)

    return r.stdout.strip()

def test_a_portion_holding_only_a_namespace_subpackage_is_hashed(monkeypatch, tmp_path):
    """Portion b holds only ns/sub/mod.py, no __init__.py anywhere: pkgutil.iter_modules lists nothing in it, but Python imports
    ns.sub.mod from it.  Editing it must move the digest."""
    (tmp_path / "a/ns").mkdir(parents=True)
    (tmp_path / "a/ns/m.py").write_text("X = 1\n")
    (tmp_path / "b/ns/sub").mkdir(parents=True)
    (tmp_path / "b/ns/sub/mod.py").write_text("Y = 1\n")
    locs = [str(tmp_path / "a/ns"), str(tmp_path / "b/ns")]
    assert _imports(tmp_path, ("a", "b"), "import ns.sub.mod as m; print(m.Y)") == "1"
    d0 = _digest(monkeypatch, locs)
    (tmp_path / "b/ns/sub/mod.py").write_text("Y = 2  # edited\n")
    assert _imports(tmp_path, ("a", "b"), "import ns.sub.mod as m; print(m.Y)") == "2"
    assert _digest(monkeypatch, locs) != d0


def test_portions_that_overlap_never_share_a_digest_across_orders(monkeypatch, tmp_path):
    """Portions a and b both hold ns/x.py: sys.path order picks which one Python imports.  The two orders must not get one digest;
    refusing the overlap is the fail-closed answer."""
    for p, v in (("a", 1), ("b", 2)):
        (tmp_path / p / "ns").mkdir(parents=True)
        (tmp_path / p / "ns" / "x.py").write_text(f"V = {v}\n")
    imported = {o: _imports(tmp_path, o, "import ns.x; print(ns.x.V)") for o in (("a", "b"), ("b", "a"))}
    assert imported[("a", "b")] != imported[("b", "a")]
    digests = {}
    for o in imported:
        try:
            digests[o] = _digest(monkeypatch, [str(tmp_path / p / "ns") for p in o])
        except ValueError:
            return
    assert digests[("a", "b")] != digests[("b", "a")]


def test_todays_digest_is_the_one_portion_walk():
    """On today's layout every package has one portion, and the digest is the old per-portion walk, byte for byte."""
    h = hashlib.sha256()
    for name in ("verity", "verity_flock", "circuit_check", "verity_vllm", "verity_pouw"):
        spec = importlib.util.find_spec(name)
        assert spec is None or len(spec.submodule_search_locations or []) <= 1, (name, spec.submodule_search_locations)
        for root in (spec.submodule_search_locations or []) if spec else []:
            for f in sorted(Path(root).rglob("*.py")):
                h.update(f"{name}/{f.relative_to(root).as_posix()}\0".encode() + hashlib.sha256(f.read_bytes()).digest())
    assert h.hexdigest() == CS._source_digest()
```

## Smallest fix (tested)

1. Hash every portion, by dropping the `iter_modules` filter.
2. Raise `ValueError` when two portions define the same module. `x.py` and `x/__init__.py` count as the same module, and the
   check applies only across portions, not within one directory.

The only test this changes is the PR's cwd assertion. A directory that joins the namespace from the cwd now moves the
digest. That is a cache miss, never a hit. If those misses matter, exclude the cwd's portion by its location (the `''` or
`os.getcwd()` entry of `sys.path`), not by what it contains.

The diff below is against the merged tree; its flock files are identical to c8443978e. With it applied, the full
`test_class_statement.py` plus the red-team file passes (result at the end of this note). The digest on today's tree is still
the old value, as `test_todays_digest_is_the_one_portion_walk` checks.

## What holds

- **The tool closures (question 2).** `package_paths(TREE, "verity", "**")` resolves to `packages/verity/src/verity/**`, the
  old glob. `FLOCK_PURE.closure` and `FLOCK_CLASS_SWEEP.closure` are equal to their old lists, so all 127 tracked files are
  covered, including the 20 that are not `.py` (JSON, `PROTOCOL.md`). When no root holds `verity`, `package_dirs` and
  `package_paths` raise `LookupError` at import, so a missing package fails instead of passing with an empty closure.
- **Binding.** Each entry is `name/<path under the package>\0` followed by the file's 32-byte sha256. No path contains
  `\0`, so the encoding is unambiguous, and the digest is bound to both path and content.
- **Pinned values.** On today's tree the digest is byte-identical to the old per-portion walk, so no stored stage key is
  invalidated.
- **The PR's tests**, run from a `/tmp` worktree of the merged tree with `__file__` resolving into it: `test_class_statement.py`
  passed 21 of 21. In `test_lean_verifier.py`, `test_the_reference_vectors_exist` and the template, Q_word and format
  agreement tests passed 5 of 5 with `lake` present and nothing skipped. Two of these first failed because their subprocess
  ran the system `python3`, which lacks pytest; with the venv on `PATH` they pass. That is the test environment, not the PR.

## Non-blocking

- `package_dirs` reads the working tree on disk (`import_roots_dir`), not a git revision. A closure computed while another
  revision is checked out names today's directories.
- `_source_digest` hashes only `.py` files, not data files the staging code might read. That was already true before this PR.
