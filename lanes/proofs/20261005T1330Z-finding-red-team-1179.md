## Non-blocking findings

1. **The cross-check no longer exercises Lean's verify on sessions with a drawn, unproved law.**
   - Where: `backends/flock/verifier/lean/Main.lean:384` refuses those sessions at setup, before `verify` runs. In
     `backends/flock/verifier/agree.py:231-239`, a drawn set's expectation becomes "rejected with the drawn WHY", and a
     fuzz case with no expectation checks only the Lean refusal, not upstream's verdict.
   - Effect: on the drawn sets, no accepted session and no mutant reaches Lean's checks, so the agreement test checks only
     the refusal there. The PR body acknowledges this. It's a coverage loss in the cross-check, not a soundness gap: the
     sessions are refused.
   - Smallest fix (follow-up): apply `drawLaw` last, as the draw-less refusal already is (`Main.lean:426`). The drawn sets
     would then use agree.py's `last` path (`agree.py:223-230`), which counts a session refused last as having passed
     every check and compares it with upstream as before.
2. **The model copies of `recordDraw` and `setupOf` are faithful by inspection, not by construction.**
   - `Exec/Event.lean:57,67,73` copy `Main.lean:262` and Main's `setupOf` closure term for term (I diffed them).
   - Nothing stops them drifting apart. The planned follow-up (`Flock/Verify.lean`, a per-session setup that `Main` calls
     and the model reads) would close this.
3. **ZK covers less than soundness does, which is expected.**
   - Under `--zk`, a public-output statement has a zero-knowledge view only at one table: `ViewZ` sits inside
     `∀ hn : I.count ≤ 1` (`FailClosed/One.lean:631-652`). `SoundZJ` covers every number of tables.
   - This is a ZK claim, not soundness. Any doc or table that cites ZK for public outputs at count ≥ 2 would overclaim; I
     found none in this PR.
4. **The two scope checks read different things to refuse public inputs, with the same result.**
   - Rust `proved_scope::statement_why` (`backends/flock/live/src/proved_scope.rs:84`) reads the circuit's
     `public_inputs` ports.
   - Lean `statementRules` reads the `--public-inputs` flag. The soundness model fixes the flag to false
     (`FailClosed/Scope.lean:81`), which is sound because Main refuses every session that sets it.
   - Both refuse such sessions; only the stated reason can differ.
5. **Pre-existing, not introduced here:** a `verify` call with zero sessions exits 0 without a VERDICT line. Nothing in the
   theorem depends on it.
