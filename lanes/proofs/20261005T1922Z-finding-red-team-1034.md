# Red-team: #1034 at `a828bc2549bf9339b08456ee244b2924ab486e89`: GRANT

#1034 is PoUW's hidden tile check under C-Flock `--zk` at K=4096, stacked on #864 (`cursor/pouw-row-seg-a-rows-e3fa`).
Its base hasn't moved: it is still `20b17cde9`, the head proofs granted in note:proofs/20261005T1452Z-finding-red-team-864.

**Scope.** The red-team rule (`tools/check/queue.toml`: `backends/flock/` minus `README.md`, `PROTOCOL.md` and `*/tests/*`)
catches two files, `verity_flock/circuit.py` and `verity_flock/class_statement.py`. Against the merge base `20b17cde9`,
the Lean verifier, `live/` (the Rust verifier), the patches and `ir_lower.py` are byte-identical. Main still has the guard
this PR removes, so the change is new here, not carried over from main.

**What changed.**

- `compose` now takes public input ports beside bit rows. It used to raise NotImplementedError. It still requires a bit
  length on every input row.
- `class_statement` adds `unit_lowering` and `stage_unit`, a unit Definition on named u16 rows with the public ports'
  leaves first.

Neither weakens what C-Flock proves, and neither discloses a hidden row.

**What I checked.**

1. **`compose`.** Only the guard changed, and the code after it is the same, so every statement that composed before
   composes to the same bytes.
   - I ran the base's ten test files that compose, quick and slow, against the head's and then the base's `verity_flock`.
     All 71 `compose` calls (35 tests, five with public inputs) gave the same SHA-512, and the six refusals gave the same
     messages.
   - A port becomes public only by being named in `public_inputs`. It then leaves the rows, and its leaves are zero leaves
     of `leaves_in`, indexed in `leaves_public`. `public_blocks` refuses a row leaf in a public port's 128-bit word.
   - Both verifiers recheck all of this from META, whatever the row schema (Lean `HmIn.parse`, Rust
     `check_public_inputs`). They drop the Δ copies of public leaf bits and bind those bits through the `in` regions to
     the public file's words.
   - The Lean verifier holds those words to its own `--public-inputs` file: the port list must be canonically equal to
     META's, in order, and every word is compared. META is inside the circuit text, so it is part of the statement's
     identity.
   - My tests: the Lean verifier refuses the honest circuit with its own file's ports in another order, a public file whose
     two ports' words the prover swapped, and one flipped public word.
2. **`unit_lowering`.**
   - It is `IL.lower` of the Definition on leaves cut from u16 input words: one unit, every port `Array(w, Value(16))`,
     dtype u16.
   - It refuses a row that isn't whole u16 words, and a parameter or row that isn't placed exactly once. Outputs are zero-padded
     to whole words.
   - `stage_unit` checks every instance against the IR reference (`evaluate`).
   - The verifiers require no leaf order, only that no row leaf shares a public word. PoUW's anchor regions fill whole
     128-bit words (`region_words` refuses otherwise), so the rows start on a fresh word. My test shows that a 3-word
     public port is refused.
   - Zero knowledge:
     - My test shows that the public file holds only its header, each row's `b ‖ c` and the declared public words. No row
       word appears in it or in the circuit text.
     - The `--zk` patch is PCS-level hiding, and an `in` region constrains only public or zero columns.
3. **Circuit rule.** `unit_lowering` registers no Definition, template or served row. It lowers an existing Definition into
   a statement, so `circuit-check` has nothing new to bind, and the PR's "no target added or changed" holds (but see F3).

**Not blocking:**

- **F1.** `compose` doesn't refuse an input port named twice.
  - A row named like a public port is filtered out with it, so the hidden row's leaves become public words in META and in
    the public file's tail. `test_a_row_named_as_a_public_port_is_refused` shows it.
  - Both verifiers refuse such a statement ("a port named twice"), so nothing false is accepted. But the stager has
    already written that array into `pub.bin`.
  - This is on main too, for `row/v1` rows (#846). `stage_unit`'s free row names make it easier to reach.
  - Fix: one check in `compose` that `sub.inputs` names are distinct.
- **F2.** The Lean statement checks cover bit rows beside public inputs, but the Lean soundness proofs don't cover
  row-seg or v2 rows (`ProvedScope`). Once #1179 lands, `verify` refuses these statements. This was already noted for #864,
  and the PR body names it.
- **F3.** `benchmarks/pouw/hidden_zk/core3_scratch.py` and `hash_scratch.py` are C-Flock pieces (Boolean lowerings of core
  and PoUW primitives) patched in at run time. `circuit-check` doesn't see them. Their results are labelled scratch and must
  not be cited as the registered lowerings' results. They are out of this grant's scope.
- **F4.** `hidden_zk/stage.py` derives every salt from a public constant (`sha256` of a label and K). So the job's row
  commitments hide nothing from someone who reads the job, and its `--zk` runs show cost and verdicts, not hiding. That is
  fine for seeded benchmark rows, and `stage_salts` documents it.
