**What I checked.**

1. **`mask_rank_ok` returns the Gauss–Jordan's `(rank, ok)` on every input.**
   - The algorithm: each row is reduced against a basis keyed by lowest set bit. Every set bit of a basis vector lies at or
     above its pivot, so a reduction clears the row's lowest bit and sets nothing below it. The loop therefore ends, and a
     row is inserted only when its pivot is new.
   - The rank: the basis vectors are independent (their lowest bits differ) and span exactly the rows read, so `rank` is the
     GF(2) rank of the rows read.
   - The early stop: the loop stops only at `rank == 128 k`, the column count, which no later row can raise. So the result
     equals the Gauss–Jordan's for dependent, zero, too few or no rows, and with no points (both give `(0, true)`).
   - The skipped words: `eq_word` is pure and total, so leaving words unread changes only the time.
   - What it guards: this is the prover's refusal at the opening's label. With a rank below `128 k`, `s_hat_v` would leave
     with a non-uniform part. The answer is unchanged on every input, so no mask that fails to hide gets accepted.
   - Timing: how early the loop stops depends on the claim points and the mask's word positions, both of which are public.
   - The oracle: `mask_rank_gauss_jordan` is main's function verbatim (I diffed it against `origin/main`).
   - Where the oracle runs: the proved-size oracle is `#[ignore]` only under `debug_assertions`, and upstream's release
     profile sets none. So `check_build.sh test` (check's `flock-rust-tests`, `cargo test --release`) runs it. It passed
     there, at 2048 × 2^17 and 512 × 2^19 words.
2. **`f128s_lanes` is the sequential draw, word for word.**
   - Addressing: `fill_at` sets the stream (`purpose | table << 32`) and the word position (8 · index, where an index is 32
     bytes) on every call. A word is therefore a function of (seed, table, purpose, byte address) alone, and no other
     `ProverRng` method reads the generator's position.
   - Piece offsets: piece `c` of lane `i` starts at word `4096 c`, which is byte `65536 c` and index `(i << 32) + 2048 c`.
     That is what the code computes.
   - Coverage: `par_chunks_mut` partitions each lane, so every word is written once, from its own address. Lanes start
     2^37 bytes apart and are at most 2^22 words (2^26 bytes) long, so they never overlap.
   - The generator: each worker's clone carries the key and the table. The original generator is not advanced, and nothing
     after it relied on its position.
   - So no address is read twice or skipped, across lanes, tables, or after the generator has read another stream.
3. **`make_zkrep`'s per-rep copy is the old clone.**
   - The new `Level0Zk` literal names all six fields, which the compiler enforces. `queries0`, `t_pad` and `tamper` are
     `Copy`, `rep` is set as before, and `pads` is the same `clone()`.
   - `extra[i]` is `par_iter().copied().collect()` into a new `Vec`, and rayon's indexed collect keeps the order.
   - Each rep gets its own allocations in its own `Arc`, and no lock is held across either new parallel section.
4. **The prints carry only public shape and time.** `ZKL0` prints the lane count, `t_pad`, the extra lanes' length and its
   seconds, and `ZKPRE` prints two durations. At K = 4096 `ZKL0` reads
   `{"extra_words":4194304,"lanes":68,"t_pad":436,"s":0.058}`.
