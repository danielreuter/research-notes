# Decision draft: the fastest practical ZK prover for batched exact BF16 dot products

*Synthesis lane, FINAL pass from `main` at dfb1618 (= e9e25bb + a-kernel-a100-2's close-out; 2026-09-22 ~12:30 UTC; passes 1-2 at ff651a8 / 451b6e8), for the
coordinator to correct before ~14:30 UTC. Every number carries its ledger lane and run id (233 entries, 50 lanes);
labels are the ledger's except where a red-team verdict downgraded one (downgrades stand; nothing is upgraded).
Tables between `<!-- BEGIN TABLE -->` markers are regenerated by `python -m verity_numerical.bench.decision_tables
--write`; the prose is not. `[COORDINATOR]` marks anything taken from the coordinator's messages rather than from a
report or ledger. No PENDING cells: the A100 pair the coordinator expected at ~12:40Z landed on main at dfb1618
(r20260922-115019-03ea) and is in the table. Appendix: `note:r20-proof/synthesis/20260922T1214Z-draft-decision-draft-appendix`.*

The question: which architecture is the fastest practical zero-knowledge prover for large batches of the fixed exact
NVIDIA BF16 dot-product relation (one VU = 96 chained `mma.sync m16n8k16 bf16` transitions, K = 1536, c_0 = +0, final
BF16 RNE), at soundness 2^-128, full batch B = 4096 on the same hardware, with latency (sequential challenge depth x
RTT) as a first-class axis, with honest labels.

## 1. Verdict in five lines

1. **B-Ligero (direct Ligero-style prover, torch + SIMT kernels) is the fastest full-batch prover and the only one
   with an audited, independently verified ZK label.** Same card (one H100, gate4-h100, checker v1, both statement-bound,
   both verified): **B-Ligero non-ZK 2.39 s vs A 5.02 s** (0.583 vs 1.225 ms/VU; 5.92e7 vs 1.24e8 x native;
   r20260922-092841-94ac vs r20260922-091718-45c3). On the L40S the repaired ZK prover runs **1.394 s interactive
   (COMPLETE_ZK_BACKEND) / 1.500 s Fiat-Shamir (COMPLETE_HVZK_BACKEND)** per 4096 VUs, 2^-128.05 / 2^-128.04 union
   bounds, verifier ~1 s, depth 3 / 1 (b-zk-fix r20260922-105905-2021; labels EARNED by red-team-zk2
   r20260922-112029-2db3; Rust verifier 108/108 honest, 264/264 rejected, b-verifier-2).
2. **A's independently verified number is 1.875 s** on an H100 (a-gpu2 prover, Rust verifier accepts after a-protocol-diff
   pinned the sumcheck variable order; 1320/1320 mutations + 44/44 negatives rejected; r20260922-104038-eabb), a
   different pod and run than gate4's 5.02 s. e2e at RTT 0: 5.19 s with the pod's 16-thread Rust verifier (3.28 s), or
   2.82 s with the 1.00 s 12-thread verifier (a-verifier-2 r20260922-105647-c947). A is NON_ZK_PROOF_DIAGNOSTIC: no ZK
   layer built. Same-card A vs B-Ligero at their *best* builds has not been run; on the numbers as they stand
   (different cards) B-Ligero non-ZK 1.366 s (L40S) vs A 1.875 s (H100) is ~1.4x, and A's depth is 438 vs B's 1-3.
3. **Labels.** B-Ligero FS = COMPLETE_HVZK_BACKEND, the only *transferable* ZK proof (assumptions [hash,
   random-oracle]). B-Ligero interactive = COMPLETE_ZK_BACKEND but **only with a live/designated verifier**: interactive
   proof *files* are not transferable -- the simulator as cheating prover produced 49/49 accepted files for false claims
   in both file verifiers (b-verifier-2 D7). C = COMPLETE_ZK_BACKEND, designated verifier, 1255.6 s + 20.88 GB per batch
   (c-compress r20260922-080520-71b6). B-AIR = NON_ZK_PROOF_DIAGNOSTIC, now statement-bound on main (b-bind 8437aa5),
   best 32.80 s at 2^-128.6 on a CPU (b-air-v2 r20260922-090904-cd75). The pre-fix B-Ligero `--zk` rows (b-zk, b-ligero2,
   gate4 HVZK) stay downgraded to NON_ZK_PROOF_DIAGNOSTIC (red-team-zk F1 q leak was real for that code).
4. **Every soundness hole found tonight is fixed on main** (section 4 table: 12 entries, 8 candidates' holes + 2 tooling
   faults), and every fixed number is within noise of the unfixed one where a same-box measurement exists (B-AIR
   binding 199.4/182.8 vs 197.6/201.8 s; lead.window +3%; B-Ligero q mask 1.41 -> 1.394 s; A R16 fix was *faster*).
   Both A GPU incidents (vy-g5 rejection, A100 "fractional sum") have one tooling mechanism -- a stale Triton disk
   cache serving X^6-31 binaries to the X^6-22 tree (a-kernel-a100; confirmed on the A100, a hypothesis for vy-g5) --
   not arithmetic. A's same-card A100 pair on merged main, both Rust-verified: **v1 2.969 s / checker-v2 2.450 s**
   (a-kernel-a100-2 r20260922-115019-03ea) -- the first independently verified checker-v2 GPU number and the first
   time v2 beats v1 on a real prover (0.83x). Open: D1 (B-Ligero Python verifier does not check a file's params meet
   the target), b-bind's v2-header residual (LogUp table digest bound via the preprocessed commitment, not absorbed).
5. `[COORDINATOR]` must decide: (i) whether the headline is the same-card gate4 pair (2.39 vs 5.02 s) or the best-build

   designated-verifier systems) or live (then B-Ligero interactive 1.394 s); (iii) the leaf/v2 protocol change --

   (iv) whether the A100 pair (A v1 2.969 / v2 2.450 s, no current-build B on that card) should be shown next to
   gate4's H100 pair -- B-Ligero's only A100 run is anchor-a100's early torch prover (1.78 ms/VU at 85 VUs/proof,

## 10. Authentication / Verity integration

Every row in the like-for-like table except SP1 is `authentication: excluded`: the proofs bind a statement `(A, B, y)`

## 11. What the architecture space says

CHECKER -> LOOKUPS -> WITNESS -> COMMITMENT/ENCODING -> ZK -> GPU. Per stage, what tonight established and which
direction it triggers or closes (C: binary/word arithmetisation; D: specialised Ligero; E: hybrid GKR + committed
checkpoints; F: better commitment/encoding).

- **CHECKER.** v2 is the largest single win of the night and it is candidate-agnostic: 4.8x on A, 2.6x on B-AIR, 3x
  fewer Ligero rows for B-Ligero (modelled). It was proven equivalent (z3 10/10) before it was priced. Remaining
  headroom per unit is 33 mul / 9 lin / 89 lookups: the lookups now dominate, and v2 got there by replacing every
  *decomposition* (hint + range check + recombine) with a fixed-table lookup whose output the lookup argument binds
  (`note:r20-proof/checker-min/20260922T0727Z-report-checker-min` 1-2; only 10 range chunks per unit remain). **Triggers C** (binary/word arithmetisation) only as
  the next step past v2 -- v2 already took the word-table route for align/normalise/decode; C would have to beat
  89 lookups/unit, not 306.
- **LOOKUPS.** LogUp was worth 2.9x on B-AIR (173.24 s limbs -> 60.14 s) and is the cost floor of A (the 3.5M-row
  SHIFT table's multiplicities are 5.14M of A's 109M committed elements per proof at v2, gkr/PROTOCOL.md 14.1). Every
  lookup-path soundness bug tonight (U1/U2, R16,
  2^-93.8 at BabyBear^4) was in the lookup argument, and BabyBear^4 cannot reach 2^-128 with 2^25.7 lookups; ^6 costs
  +43% on B-AIR (22.92 -> 32.80 s). **Closes** "BabyBear^4 at 2^-128" for any LogUp design at this batch size.
- **WITNESS STRATEGY.** A commits everything (26.6k-44.9k elements/VU) and runs 328-355 sequential rounds; B-Ligero
  commits 337k elements/VU (8x A) and runs 3 rounds -- and is 3-18x faster. Commitment *volume* is not the cost; the
  *sequential* structure is (A's sumcheck rounds are launch-bound on the GPU: a-fusion's 10-stream logUp and fused
  rounds recover only 1.5x). **Direction E as "checkpoints every m units" is closed** by `note:r20-proof/latency/20260922T1111Z-report-latency` 6: m = 2 is depth
  386 at 1.5x work, m = 4 is 746 at 2.5x -- deeper *and* slower. What `note:r20-proof/latency/20260922T1111Z-report-latency` does keep open for A is the *committed
  cut* family (commit the R16 tree at levels [16, 21] + the depth>=3 checker wires: depth 140 at 1.031x, +20.9%
  committed) -- i.e. the hybrid that survives is "GKR + commit the intermediate lookup-tree levels", not
  "GKR + checkpoint the chain". Either way A keeps its proof size (34-42 MB vs 110-122 MB) and gets to 140, not 3.
- **COMMITMENT / ENCODING.** Hash is solved on GPU (b-commit fused encode + BLAKE3 column hash 46.7 ms for the 20.4 GB
  B-shape codeword on a 4090; anchor-a100: 98.0 ms on the A100, BLAKE3 the best hash there). Ligero rate 1/4 with t=192
  is at the union-bound edge (2^-128.05). Exploiting the *structure* of r^T A (b-lintest: the linear test is a per-row
  scalar times one of M = 3 fixed rows) cut B's 4090 model from 258.7 ms / 6.41e6 to 116.4 ms / 2.89e6 (2.2x,
  r20260922-073017-0924). **Triggers F** only for A (its 33.9 MB
  proof is dominated by the t = 192 Ligero column openings and Merkle paths -- `[COORDINATOR]` verify the share from
  the a-gpu bundle; a FRI/STIR-style folding would cut proof bytes but add depth) and **D** for B-Ligero
  (the 25-sub-batch structure is an artefact of the 65,536-column device layout; one 4096-VU codeword would remove the
  union-bound tax and 24 of the roots).
- **ZK.** Cheap everywhere: +3% measured (B-Ligero), +0.002%-1.6% modelled (A, B-AIR) -- and *hard to get right*:
  the first built ZK layer leaked every accumulator through one unmasked message (red-team-zk F1) and its simulator

  (red-team-zk2) at +2% (interactive) / +8% (FS) prover cost. The discriminating axis is whether it is built *and
