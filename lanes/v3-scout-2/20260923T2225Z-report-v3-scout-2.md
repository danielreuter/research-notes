### What the table says

1. **On Hopper and Ampere, v3 is slower than v1 at each relation's best depth**, unlike fp8-ada on the 4090 (open-fixes: v3
   −13.8 %). fp8-hopper: v3 p4 0.1449 vs v1 p4 0.1187, **+22 %** (v3 slower in 4/4 paired rounds). bf16-hopper: v3 p8 0.2135 vs v1 p8
   0.1862, **+15 %**; at p4, 0.2449 vs 0.2252 (+9 %). bf16-ampere: v3 p4 0.3370 vs v1 p8 0.3089, **+9 %**. The predecessor's
   single-round "bf16-hopper-v3 −19 % at p4" came from a slow first v1 round (0.2955); v1's other three rounds were 0.206–0.236.
2. **Why: hint generation.** v3 cuts encode+commit (fp8 0.016 vs 0.025 s; bf16 0.026 vs 0.045 s) and proof bytes (−28 % / −30 %),
   but its hints cost 0.049 s (fp8) and 0.088 s (bf16) at p4, against v1's 0.010 and 0.021. On the A100, v3 hints are 0.12–0.15 s,
   37–44 % of the wall. On the fast Hopper arithmetic this fixed cost dominates, so the lever is the fused hint kernel (`hints-fused-2`),
   not depth. If hints-fused lands, expect v3 to reach v1 or beat it on the H100: its non-hint phases are already smaller.
3. **Depth:** fp8 (13 sub-batches) is best at **depth 4**; depth 8 is slower for both v1 and v3 and far noisier. bf16 (25 sub-batches)
   is best at **depth 8** for both v1 and v3 on the H100 (−13 % for v3 vs p4). On the A100, v3 p4 and p8 tie (0.337 vs 0.336), so
   use p4 at half the memory. Depth 2 is 1.4–1.7× slower than depth 4.
4. **`--batch 32768` fits in 80 GB (peak 18–57 GiB) but is 3.2–7.6× slower** than the same relation's best l = 16384 cell for the
   same 4096 VUs (v3 3.2–3.7×, v1 7.1–7.6×; bigger NTTs, fewer sub-batches to overlap), so it is not a candidate. Single round each;
   the gap is far outside the noise.
5. **Noise:** the H100 host is shared (loadavg 5–50 across the runs). The same cell moved up to 64 % between rounds (bf16-hopper v1
   p4 0.206–0.296; fp8-hopper v1 p8 0.115–0.188). Only medians over ≥ 3 rounds, with the v3/v1 order alternated, are decision-grade.
   The device wave should do the same.
6. Caveats for Table 2: each relation proves its own instance set (manifests above). The v3 and the Hopper v1 sets are synthetic;
   the A100 v1 runs (`bf16-ampere`, `vu.py`) use the frozen `bench-instances/v1` set (059103cf). Several depth ≥ 4 runs print a
   measurement-contract warning ("buckets and joints sum to … more than t.total by over 1 %: something is double-counted";
   b3p8, f1p4, b1p8L, a3p8r2, f3p8r3, b3p8r4, b1p8r4). It comes from overlapping phase buckets under pipelining. Validation passed
   and t.total is the wall clock; the phase columns are indicative only at depth ≥ 4.
