## 0. The problem, in one paragraph

A server holds an encoding C of model weights W (W adversarial, possibly all zeros, known to the server). A verifier samples k random encoded blocks and checks them against tags. We want: (security) any retained state of at most r|C| bits, r = 18/19, passes a round with probability at most 1% plus a bounded cryptographic error, against an adversary that knows W and all public data and may hold any function of the encoding; (performance) decoding on every use, fused into the matmul, costs less than 10% of the plaintext matmul-sequence runtime at low batch (target), with 2× as the "interesting" threshold; (storage) |C| plus everything else persistent at most 1.05|W|. Two settings differ in who encodes: a **public encoder** (the server encodes its own data; phases 1–3) or a **trusted encoder** whose secrets are erased after encoding (phase 4). Two security models differ in whether a **deadline** exists: with a deadline, regeneration only has to be slower than Δ; without one, regeneration has to be cryptographically infeasible.

Two facts organise the chart (T1, `research/trusted4/theory/template_bound.md`, lemmas 3 and 4, being written tonight):

- With a public encoder there is no untimed security: the server can store W and re-encode on demand. So public-encoder options live in the timed model and need a sequential-cost argument (depth-robust graphs). Branch D.
- With no deadline, raw-block audit soundness given W is equivalent to Moran–Wichs incompressibility given the message. So trusted-encoder, no-deadline options *are* incompressible encodings, and the only free choices are the idealisation (standard model, random oracle, ideal permutation) and the public-parameter accounting. Branches A and B.

### A1. MW-DCR — proved, 10^7× too slow

**0. Identity.** Moran–Wichs incompressible encoding instantiated with the Damgård–Jurik group: N = PQ of 3072 bits with the top 20 bits of N set, s = 31, block = one element of Z*_(N^(s+1)) = 98,304 bits = 12 KiB. Public key pk = (N, c) with c = ψ(1, r̂) (surjective mode). Codeword c_i = Inv_td(embed(W_i) · u_i) with u_i = SHAKE256(seed ‖ i); decode f_pk(a, r) = c^a · r^(N^s) mod N^(s+1), then divide out u_i and un-embed. Trusted encoder erases P, Q, r̂. Setting: trusted encoder, no deadline, weights only. Idealisation: random oracle for the offsets (the CRS variant is excluded by the memory bound, see A5). Assumption: DCR at 3072 bits for moduli from the constrained distribution; concrete hardness is "no attack better than factoring" (NIST 128-bit at IFC 3072). Source: T1 `trusted4/theory.md` (reviewed by R1, `theory_review.md`).

**1. Security.** Proved. Lemma 1: C is indistinguishable (loss 62 · Adv_DCR, one hop for the whole codeword) from a distribution in which, given (pk, W, seed, RO table), blocks are independent with min-entropy exactly s · log₂N = 95,232 of 98,304 bits (rate 31/32 = 0.96875). Theorem 2: any state of ≤ (1 − ε)|C| bits answers a random block with probability ≤ p* = (1 − ε)/ρ + 1.1·10⁻⁵ + 2⁻⁶⁴ = 0.97794 at ε = 5.26%; a round of k blocks passes with probability ≤ p*^k + 2⁻⁶⁴ (sequential reveal, k = 207 for 1%, 620 for 10⁻⁶) or ≤ p_η^k + kη + k2⁻⁶⁴ (joint answer, k = 209 / 631). Extractor is information-theoretic in the lossy hybrid; no deadline, no t_min. Total crypto error ≈ 2⁻¹²⁰. Gaps: DCR is an assumption, not a reduction to factoring; RO heuristic for SHAKE256.

**2. Accounting.** |C|/|W| = 98,304/98,303 ≈ 1.00001; pk 101,376 bits and a 256-bit seed per model; tags are a 128-bit PRF-MAC per block held by the verifier only (99 MB per 76 GB), not on the server. Total server-resident ≈ 1.0000 |W|. Entropy rate 0.96875, margin 2.1 points over 1 − ε* = 0.9474. Audit block = decode tile = 12 KiB.

**3. Cost.** Measured (mw3, GMP on the CPU pod, `mpz_powm` with a 95,232-bit exponent modulo 98,304 bits): 92 s per 12 KiB block single-threaded, ≈ 3·10⁷ 64-bit-limb MACs per decoded byte as GMP executes it and 2–3.5·10⁸ 32-bit MACs schoolbook (T2's corrected conversion, twins.md row 1a; the 10⁴ figure that stood here was the Φ-hiding RSA figure). B2's H100 CGBN reference for the same shape (Paillier, mod N², exponent N, s = 1): 3·10⁴× at 2048-bit N — s = 31 is ≈ 10³ more. Bytes moved per decoded byte ≈ 1.0 codeword + 1.0 XOF output (regenerated, ≈ 7 int32/byte). Serial depth: one exponentiation per block (≈ 10⁵ dependent modular multiplications). Against a 2× budget of 8 int32/byte the shortfall is 10⁷×; no batch size makes it fit (G1 `region.md` §5.1: never reaches 2.0 at any b). KV: not applicable (trusted encoder).

**4. Attacks.** None beyond factoring; the theorem covers arbitrary retained state, cached answers, algebraic and shared representations. The Coppersmith attack of fam3 does not apply (the map is not a low-exponent permutation of a known image).

**5. Verdict.** Proved-and-priced; the program's reference point. Probability of ≤ 2× or ≤ 1.1× at low batch: 0 (measured). What would change it: nothing about this construction; a different forward map is needed.

**0. Identity.** MW §6.2 surjective lossy function in a ring or module: y = round_p(A x) in R_p^d with A in R_q^(d×m), codeword x with discrete-Gaussian coefficients of width s (compact in the coefficient domain), MP12 gadget trapdoor for preimage sampling; lossy twin A = aS + E (rank-plus-noise). LWR-style rounding is the same object. Setting: trusted encoder, no deadline. Model: standard (ring-LWE) plus RO offsets. Sources: T2 `trusted4/constructions.md` §3.1 and §6; R2 `constructions_review.md`; T1 `template_bound.md` (theorem form, pending tonight).

**1. Security.** The MW proof goes through for this family (surjective mode regular by leftover hash, lossy image small, indistinguishability from ring-LWE) — that is exactly why its parameters cannot be compact. Not the issue.

**2. Accounting.** Feasible at expansion 1.047 and entropy rate 0.970, but only with blocks ≥ 47·L² bits: ≥ 5.9 MB closed-form (R2; T1/R4 joint minimum over feasible points 9.7 MB; 16–18 MB in T2's sweep, 31–82 MB at the cost optimum) with an idealised preimage sampler that no algorithm achieves, 3–40 GB with MP12. No 256 KB tile exists at any r for MP12; only at r ≤ 0.6 idealised.

**3. Cost.** Four closed-form constraints, independent of ring/module choice and of hardware constants (T2 §3.1.2 with R2's fixes): (i) block ≥ 47·L² bits; (ii) expansion ≈ L/(L − gap) with gap ≥ log₂s + 16, so expansion ≤ 1.05 forces L ≥ 21·gap (thousands of bits; a polynomial modulus gives expansion ≥ 2), and regularity forces m/d ≈ L/(log₂s + 2) ≥ 16 (partial rounding) to 41 (exact) input ring elements per output element; (iii) any GPV/Klein/MP12 sampler adds ≈ 14 bits of width excess, forcing log₂B ≥ 330 and L ≥ 23,000; (iv, R2) the Sx term forces ≥ 35 input elements per block, so the pointwise GEMV alone is ≥ 55 int32/byte and streams ≥ 37 public-key bytes per byte. Each input element needs its own forward NTT of size N ≥ 47L ≥ 2¹⁷ (the codeword is compact only in the coefficient domain). Calculator minima over ~10⁵ parameter points: 504–561 int32/byte idealised (484 with tensor-core pointwise), 737–753 with MP12; public key 51–103 B per decoded byte unbatched (≈ 0.8 at 64-block batching), 4 GB–3.9 TB total. Lowering r to 0.5 gives 87–145 int32/byte, still ≥ 9× over the 2× budget. Budget for 2×: ≈ 10 int32 or ≈ 500 int8 MACs per byte; for +10%: ≈ 0.5 int32 or ≈ 30 MACs.

**4. Attacks.** Not needed; the option is closed on cost.

**5. Verdict.** Closed. R2's probability that any MW-template rank-plus-noise lattice construction reaches ≤ 2× at expansion ≤ 1.05 and rate ≥ 0.969: 3% (5% if expansion 2 is allowed); the residual is a lossy twin that is not rank-plus-noise, for which no lattice candidate exists. The Jin–Liu–Wang–Yu Module-LWR LTF (ASIACRYPT 2025) is injective and expanding, has no preimage sampler for arbitrary targets, and its lossy mode is the AKPW13 rank-plus-noise sampler; adding the surjective extension reproduces this row. What would change the verdict: a surjective lossy function at expansion ≤ 1.05 whose lossy twin needs no rounding gap ≥ log₂s + 16, or an error in expansion ≈ L/(L − gap).

### B1–B3. Ideal-permutation encodings

Walkthrough in `trusted4/tdp.md` (B1; calculator `tdp/params.py`). **R3 review (`tdp_review.md`, own reproduction `review/tdp_check.py`): Theorem B1 passes in the ideal model with two tightenings (the +1.44 is proof slack; the sequential log2 k disappears with one shared replay; proved loss log2 T + log2 g, so n = 4096 lands 0.17 bits/block short of rate 0.969 at k = 207 and n = 4352 passes); the simultaneous-reveal sketch double-counts log2 R (k = 347, not ≈ 650). Main finding: Assumption RSA-IC is false as stated** — a shift-and-kangaroo attack (store v_i = c_i·h^(−j_i) chosen offline to be t bits shorter; recover j_i online as an interval discrete log of y_i·v_i^(−e) = (h^e)^(j_i) in 2^(t/2) kangaroo steps; brute-force the low bits) saves ≥ 204 bits per block under the assumption's own quantifiers, 154 with offline work capped at 2^100 per block, against the 145.5 bits it tolerates; verified at toy scale. Consequences: no RSA exponent reaches 0.969 at n ≤ 4608; B3's deadline premise fails (the compression is bought offline); "e ≥ 167 → 257" keeps its arithmetic and loses its premise; a repaired assumption would be a bespoke conjecture below the RO heuristic in assurance, needing n = 5120–6144 at 1.5–2.4× the cost with an open-ended deviation list. The ideal-model theorem is untouched: the attack is a proof that RSA is not an ideal permutation for this game. **All applied by B1 in 5904076** (new §4.2.7 writes the attack up with R3's budget table; `params.py` gained `proved_old`, tightened `conj` and `rsa_kangaroo` models); tdp.md is review-complete. B1's revised line: every known trapdoor permutation is factoring-based and group-homomorphic, so §4.2.7 applies to all of them; P(B1 ≤ 2× with the ideal-model proof accepted) = 0.01, ≤ 1.1× = 0; B3 → 0.01. Cost measured by B2 in `trusted4/tdpcost.md` (GMP on t4cpu; CGBN on the H100, 131,072 codewords per launch, best of TPI 8/16/32 and window methods; data with `.cmd` sidecars under `tdpcost/out/`).

## 4. The open problem, stated once

Source of truth: T1 `theory/template_bound.md` §5 (Specification 5.1, review-complete after R4) and T2 `twins.md` §11 (reconciled; R5 must-fixes being applied). Wording agreed by the coordinator from both.

**What is proved.** The audit's property is incompressibility of C given W (Lemma 3: raw-block soundness at (k, δ) ⇔ INC(β, π) given W, nothing weaker suffices, and HILL entropy of C given W is one sufficient route, not the target). A W-dependent setup buys nothing cryptographically (Lemma 2, Cor. 8.1: a p-bit pp moves at most p bits of target dependence out of C). `Eval(X, C) = XW` is a decoder (Cor. 8.2: standard-basis rows recover W; if the map into the MMA is bilinear, Gaussian elimination compresses C to α − n bits, so every security-producing nonlinearity acts on C *before* the multiply-accumulate and its per-byte cost is the whole question). Every public encoder is timed-game material (Lemma 4). Every rank-plus-noise lattice twin *under the MW certification route* costs ≥ ≈ 250 int32 per weight byte at expansion 1.05 and needs ≥ 9.7 MB blocks (Theorem 1 bounds the rate the template can certify; it does not exclude a direct INC proof for the same arithmetic object, of which none exists; word-size moduli only above expansion 1.33). Factoring-based twins are capped at 25% lossiness except Damgård–Jurik (Cor. 8.4), which is proved and 10^7× too slow.

**What is measured.** The fused decode→GEMM kernel at decode batch b ≤ 8 admits 0.3–0.4 int32 or 7–8 int8 tensor-core MACs per weight byte under R_seq ≤ 1.10 and 8 / 200 under 2×; the random-oracle offset alone (ChaCha8 1.28×, Philox 1.17×, bit-exact inside the GEMM; the kernel itself is 1.07× with nothing decoded) exceeds the 1.10 line, so **+10% is closed for the MW/RO architecture under every credible offset generator identified and measured** — a measured statement, not a lower bound: the one shape that could fit is a tensor-core-native PRG/hash at ≤ 7 MACs per byte, itself an unanalysed cryptographic object (phase 2's open "matmul hash as RO" question) — and 2× leaves f_pk ≈ 4.5 int32 or 120 int8 MACs per byte. Prefill chunks (b = 8,192) open 144 int32 at 2×; KV is the b = 1 column forever (§X, `region.md` §9).

**The object that is missing (Specification 5.1).** A trapdoor family, in the abstract sense of Cor. 8.3 — a secret tied to the public key that lets the encoder sample the fibre of any prescribed W-tile while the public cannot efficiently index a codeword inside its fibre — of word-level keyed maps f_pk on 1–25 KB tiles (w ≤ 32-bit words, one key for the whole model, pk within the 1.05 budget), whose forward direction costs ≤ ≈ 4.5 int32 issue slots or ≤ ≈ 120 int8 MACs per decoded byte on top of the offset, and that is *either*

- (i) an SLF*: exactly (1.03 : 1)-regular with a trapdoor sampler in the real mode, exactly 2^(−0.031·nw)-compressing in a lossy mode — the small image hidden by something other than noise (Theorem 1), unknown group order (cost; the Cor. 8.4 cap) or a detectable kernel (elimination) — with the two modes 128-bit indistinguishable given the key and no coupling between the hardness parameter and the tile size; *or*
- (ii) a single-round-per-block map with a direct INC-given-W proof in an idealised model (random oracle, ideal cipher, ideal permutation), Pietrzak/DGO19-style, without a chain (GLW20 makes any chain r = n·b·λ rounds long) — and, if defined per block, with its own composition lemma (MW20 leave composability of INC-only encodings open).

Fibre-indexing-hardness at the targets is weaker than one-wayness, and whether the object is Cryptomania is open (BHSV98: many-to-one TDFs with super-polynomial fibres from any OWF); what is not open is that no Minicrypt relaxation of the QWW21 kind replaces it. The nearest thing on record was an ideal-permutation-model encoding from RSA-e (B1: proved in the model at n = 4352, 180× measured at e = 257) — and R3's shift-and-kangaroo attack shows RSA is not an ideal permutation for this game at any n ≤ 4608, so the theorem is waiting for a trapdoor permutation that is both cheap and structureless, of which none is known; the nearest proved thing is Damgård–Jurik at s = 31 (A1, 10^7×).

**The one lattice direction Theorem 1 left open is closed at step 0 (N `trusted4/ntru_step0.md`, R6 `ntru_step0_review.md` pass with must-fixes, applied in e22ad15; 2026-09-21).** The NTRU shape — a public linear map on a box or Gaussian domain with a hidden short kernel basis, exactly lossy without rounding — fails gate G2 by theorem for every trapdoor it is known how to build. *Lemma L:* an exact linear twin indistinguishable from a regular A has full rank mod every prime dividing q (a deficiency is elimination-detectable on any domain, since A′ is public), so it leaks n·H_inf(χ) bits, the MW-certifiable rate is ≤ 1 − n/m, rate 0.969 forces m/n ≥ 1/ε′ = 32.3 for every domain and sampler, and the NTRU shape proper (m = 2n) is capped at rate 1/2 at every q — without noise nothing hides a low rank, so (I3)'s "32 per unit of secret rank" becomes 32 per output coordinate. *Theorem D (R6's dual Gram–Schmidt argument):* regularity of A·x mod q, which MW20 Def. 6.1 needs before any sampler is chosen, forces every flat-basis trapdoor (c = 1 perfect, 1.17 Falcon) to Gaussian width κ ≥ 3.73/c; with X = 1 + (0.72 + r + log2 κ)/u and Lemma L this is **L ≥ 1,690 / 1,544 bits (perfect basis / Falcon profile, Gaussian) and 1,490 / 1,344 (box) at X = 1.05**, 44–58 residues per coefficient, ≥ 330 int32/B in (I6) form; known samplers sit above (Klein perfect 1,771; Falcon's width 1,695; MP12 ≥ 5,100). Residual judgment: a hypothetical *basis-free* regular sampler could go down to κ ≈ 0.71–0.8 (random-kernel regularity, exact at small m), i.e. L ≈ 143–258 — never word size — and none is known (ADRS15 2^(m+o(m)); exact-width DGS is CVP-equivalent). The shape removed the rounding slack (I1), kept the width slack, and made (I3) worse. No lattice direction survives.

**Scope.** This chart maps the design space for *static weights*. The trusted branch cannot cover KV or any state the server produces (row K (TE): the server is its own KV encoder, and a trusted party encoding what it sends encodes the nest), so even a 1.2× trusted-weight construction would leave PoUS for dynamic state on the public/timed branch — whose guarantee is conditional on a deadline and an attacker-rate model, a different kind of claim, not the same claim less proved.

**One sentence.** *Find a public-key-flavoured trapdoor map at symmetric-key cost — ≈ 4.5 int32 per byte after the offset — whose fibres are hard to index without the trapdoor and whose incompressibility given the message can be proved either through a lossy twin not obtained from rank deficiency plus rounding, or directly in an idealised model without a chain; or accept outcome (ii): a proved-secure encoding exists (DCR), and nothing known passes the cost gate at decode batch, with +10% unreachable in the RO model by the offset alone.*

**What the relaxations buy (T2 `frontier.md`, §A6 above; D1 §3.11).** Only prefill-only serving at retention r ≤ 0.6 puts a proved construction inside 2×, and only at the model's instruction count (synthetic 87–145 int32/B measures 1.7–2.1× at b = 8,192); the real bit-exact ring-LWE decoder at those parameters measures 5.9× (ideal sampler) to 12.3× (runnable MP12), so as implemented the point is outside 2× at every b ≤ 16,384. Partial coverage fits any target linearly by shrinking the claim; nothing else moves the trusted branch.
